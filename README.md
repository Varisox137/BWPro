# BWPro

受《阴阳师：百闻牌》启发的数字化卡牌对战游戏。长期目标为双人联机对战与图形客户端。

当前已实现：核心规则引擎、正式卡牌数据（19 式神 151 卡，含协战牌）、卡组构筑与卡组码、
CLI 热座对战、FastAPI/WebSocket 联机对战（房间制、限时、断线重连）。

## 快速开始

```bash
uv sync                              # 安装依赖
uv run python -m client.cli          # 主菜单：热座对战 / 卡组构筑 / 联机对战
uv run python -m server.main         # 联机服务端（默认 127.0.0.1:1037）
uv run python -m client.net          # 联机客户端（创建/加入房间）
uv run python -m db.validate         # 校验卡牌数据库
uv run python -m db.scaffold -h      # 式神/卡牌 yaml 脚手架（生成骨架再补效果块）
uv run pytest -q tests/              # 运行全部测试
```

## 项目结构

- `core/` — 规则层：状态模型、引擎、动作原语、事件、目标解析、对局组装、调试指令
- `db/` — 卡牌数据库（YAML 按 `db/<版本包>_<拼音>/<包内编号>_<式神拼音>/` 分目录，
  式神与其全部卡牌同目录，见 `db/packs.py`）、schema、组卡校验（天梯规则，可参数化）、卡组码
- `client/` — CLI 客户端：`cli.py` 热座 + 卡组构筑；`net.py` 联机（同一 `cmd dict` 协议）；
  `tui.py` TUI 基座（prompt_toolkit 底部输入框 + 常驻状态行，非 TTY 自动回退内置 input）
- `server/` — authoritative 联机服务端（FastAPI + WebSocket，详见 `server/README.md`）
- `diy/` — 自定义卡牌 DSL（Phase 3） · `docs/` — 规则与术语文档 · `tests/` — 测试

## 已实现机制

- 引擎管线：指令校验 → 动作 → 事件 → 触发队列 → 效果块结算；状态纯数据可序列化
- 核心操作：抽牌、伤害、治疗、护甲、召唤、形态结附/消灭、升级、出击、完整战斗流程
- 战斗关键字：连击/先攻/贯通/穿刺/远程/不屈/迅捷/屏障/追猎/直击/帷幕/必杀；
  全量伤害时点批次管线；关键字三类持久性（一次性/持续/永久）；
  作用域战斗伤害免疫与敌方非战斗伤害免疫；有目标的战斗与战斗结束追加攻击
- 觉醒能力替换、攻击后到期强化、倒计时系统、投射/鼓舞、直接消灭、
  随机生成、随机分配伤害（逐点插入结算）
- 效果发起的攻击（不耗火/次数）、法术回响序列（凭空自动使用、出牌来源/方式区分）、
  反击贯通例外、力量覆写修饰、投射贯通、永久力量快照增伤、历史峰值力量差值
- 破甲（负护甲）与吸血、使用手牌前无效化、协战牌（双归属、子选项打出）
- 增强装配管线：卡牌触发器、打出装配快照、enhance 数值叠加、卡牌光环、
  战斗绑定一次性触发、计数次档随机强化（按实例去重）、牌手级持久监听
  （本局/本回合作用域）与随机四选一监听
- 响应插入使用、延迟触发、伤害上限、激怒与战斗区锁定、
  进场时形态效果与动态数值（护甲/力量求值）
- 手牌触发式光环（其他己方式神攻击后本回合瞬发）、回合结束响应排序
  （当前回合方延时效果先于对方手牌响应）、生命下限钳制与本回合受伤记账、
  无当前战斗的响应战斗牌完整流程、指定准备区目标的可选战斗
- 治疗管线扩展：治疗时/治疗后双时机（零量治疗只触发前者）、过量治疗记账
  （overheal）与转化通道、治疗反转、牌手级全伤害免疫；鬼火储存（回合开始不清零、
  累加封顶）与鬼火变化事件（付费点即时、可挂"鬼火变为 N"响应）；
  结算中交互选择（pending_choice + choose 指令：牌库顶检视挑选，
  重连续答、回合超时随机作答）；直接升级/生命设置/复活与形态实例重新结附等效果原语
- 对局流程：调度阶段、先后手经济、气绝/复活、长对局平局、调试指令系统
- 卡组：交互式构筑、天梯规则校验（4 式神 / ≤2 派系 / 各恰好 8 张 / 同名 ≤2）、
  卡组码导出导入、本地卡组文件（~/.bwp.decks.json）槽位管理（编辑/重命名/删除）与战前选卡
- 联机：房间创建/按 id 加入、随机先手、token 断线重连、调度 30s/回合 120s 计时、
  debug 对局与服务端控制台、状态按视角脱敏等基础安全（详见 `server/README.md`）
- CLI 显示：座次配色、修饰状态、关键字中文化、手牌数值段（含实时增强求值——
  持久计数未装配也按当前值显示）；
  结算明细（等级/力量/战力/生命/护甲/破甲变化与战斗、伤害、气绝、倒计时、
  回合阶段事件）与叙事日志按合并时间线排队播放（0.4s/条、块前后空行、
  嵌套层级缩进，热坐与联机一致），播放期间可正常输入操作（client/settle.py
  打印队列）；对手回合/等待期不显示输入提示符，终局按视角播报结果；
  TTY 下底部输入框 + 常驻状态行（双方牌手信息 + 回合，联机另显示倒计时）

## 主要协议

玩家指令为 `cmd dict`，热座 CLI 与联机客户端共用：

```json
{ "op": "play_card", "uid": 1, "target": { "player": 1, "shikigami": 0 } }
{ "op": "assault", "index": 0 }
{ "op": "upgrade", "index": 2 }
{ "op": "choose", "uid": 42 }
{ "op": "end_turn" }
```

- 对局阶段：`mulligan` → `upgrade`（每回合开始）→ `battle`（主要阶段）
- `choose` 仅在结算中交互选择（pending_choice，如牌库顶检视）挂起时可用，uid 为选项卡牌实例
- CLI 序号显示与输入为 1-based，协议层保持 0-based index
