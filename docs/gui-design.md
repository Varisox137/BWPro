# GUI 设计文档（调研结论 + 界面初稿）

> 前置阅读：`docs/gui-plan.md`（PySide6 桌面客户端已落地，后续迭代与维护说明）。
> 界面初稿图在 `docs/gui-mock/`（`generate.py` 生成，PIL 绘制，仅为布局示意）。

## 1. bwpemu 调研结论（github.com/menghuanmus/bwpemu，v0.7.6）

**定位差异**：bwpemu 是纯手动沙盒模拟器——抽牌、鬼火增减、生命变动全靠玩家手动按钮，没有规则引擎。BWPro 是权威引擎路线（服务端结算、客户端只渲染+发指令），二者游戏逻辑层无可借鉴之处。

**技术形态**：纯静态单页（vanilla JS + GSAP + socket.io CDN），GitHub Pages 部署前端 + 独立 socket.io 后端，无构建步骤。仅作外部项目技术参考，BWPro 不采用其前端架构。

**可借鉴的 UX 模式**（桌面 GUI 可参考）：

- 大厅房间列表（免房码直接点入）、房间密码、复制房码按钮
- 观战模式、断线重连回房间
- 长按/悬停卡牌出 tooltip 大图与效果文本
- 骰子、卡牌飞行、眩晕等轻量特效（GSAP 补间即可，不必上游戏引擎）
- 结算记录 undo（仅沙盒有意义；我们引擎是权威结算，不做）
- 单人练习模式（对我们的价值：热坐已覆盖，优先级低）
- 移动端适配（media query 缩放布局；我们桌面优先，后期再说）
- DIY 卡库：容量上限、对局自动同步、选择性导入导出——与我们 Phase 3 + BWPDIY 联动时的参考

## 2. BWPDIY 卡图渲染工具接入（已落地）

**架构红线**：BWPro 运行时不启动、不依赖 BWPDIY exe、FastAPI 或 web 服务，只 `import bwpdiy.render`。BWPDIY exe 仅用于人工标注项目配置与原图，不参与构筑、对局或自动合成调用。

接入点：

1. **`client/gui/portrait.py`**：卡组列表复用 `bwpdiy.render.duo.render_portrait` 绘制带斜方框与派系标的式神头像。BWPDIY 仓库默认 BWPro 同级 `BWPDIY`，可用 `BWP_DIY_ROOT` 覆盖；项目配置库默认 **BWPro 项目内 `library/`**，可用 `BWP_DIY_LIBRARY` 覆盖，运行时只读。editable 安装只解决 Python 导入，不替代渲染资源根定位。
2. **`client/gui/cardart.py`**：从 `library/<项目>/{shikigami,cards}/*.yaml` 读取人工标注，按 id（兼容名称）与引擎定义的版本快照日期精确匹配 `version_date`；配置日期必须是合法 8 位日期，不用相邻日期代替。卡牌的名称、类型、等级、稀有度、所属式神、派系、身材与描述等显示数据始终由当前引擎定义合成，项目配置只提供 artwork、portrait、layout、faction_style 与 frame_variant，不让旧配置文本或数值覆盖引擎数据。
3. **共用卡面**：构筑卡面、静态/运行时卡牌详情、热坐与联机手牌均调用同一 `card_pixmap`。`hand_cards_info` 同源生成中文数值段与结构化 `render`，战斗、形态、觉醒等实时身材经 `display` 注入卡面负载和缓存键，不修改引擎定义；费用、增强计数、关键字、使用条件等仍由 GUI 详情层显示。
4. **Phase 3 DIY 联动**：BWPro `diy/` 只读消费 BWPDIY `library/<项目>/` 下的式神/卡牌 yaml——"BWPDIY 做卡、BWPro 打牌"。映射层（BWPDIY yaml → BWPro yaml 口径）只放在 `diy/` 一处。

静态大卡/小卡 PNG 默认缓存到 `~/.bwpro/cardart/<sha256>.png`，头像仅使用内存 LRU、不写磁盘缓存；含实时 `display` 的变体仅使用 256 项有界内存缓存，不逐值永久写盘。缓存键包含规范化引擎负载、合并后的实际 layout、配置 YAML 内容 SHA-256、原图 `mtime_ns` 与 size 及渲染实现资源内容指纹；大卡缓存键与 manifest 不依赖 BWPDIY 版本号，版本号或 WebGUI 变化不触发失效，渲染 Python 源码与受跟踪 assets 的内容变化仍会使对应缓存失效。layout 另有 64 个元素、512px 元素尺寸的渲染预算。启动时由 GUI 线程的 `QTimer` 逐项分片消费 `prewarm_iter`，复用有效缓存并仅合成大卡与式神小卡，不预热头像；所有 `QPixmap` 创建与使用均留在 GUI 线程，状态栏显示“卡图后台同步 current/total”，不显示模态遮罩，主菜单与页面切换保持可用。重复启动复用同一任务；后台任务活跃时设置页不启动同步全量重建，关闭窗口会停止 timer 并清空 iterator。配置/原图 SHA-256、渲染资源指纹和最近合成时间写入 `~/.bwpro/cardart/manifest.json`；`prewarm_iter`/`prewarm_all` 返回成功 `entries`，失败项不进入成功清单，设置页显示成功/失败/跳过统计、最多三条失败摘要与 manifest 完整路径，下次启动自动重试，完成后刷新设置页状态。设置页仍可在后台空闲时经确认清除缓存并同步全量重建。缺配置、版本不匹配或缺图时仍调用 DIY 渲染完整卡框与文本，仅插画区域透明；透明占位是合法结果，不计渲染失败，只有渲染器自身失败才回退文字卡面。头像回退带斜方框和派系标的空槽（不绘制人物），操作按钮与运行时详情保持可用。BWPDIY 素材中异常 ICC 配置已无损移除（逐张验证像素不变）。Qt 现代 Windows 样式在空白原生窗口也会输出同类 libpng `iCCP` 警告，已确认与项目素材无关；为保持现有 UI 效果，不替换应用样式。

## 3. 界面初稿（docs/gui-mock/，1600×900）

布局参照原版游戏截图与内录视频抽帧（`gui_ref/`，版权原因不入库）。**美术定位：2D 平面布局**——原版对局是 3D 场景（斜俯视牌桌、式神 3D 模型），我们不复刻，只保留其信息层级与版式（上下半场、四角头像、扇形手牌等），卡牌/式神一律 2D 卡面占位。**双主题可切换**：浅色 = BWPDIY 羊皮纸（`#f3efe8` 纸底 / `#fffbe9` 面板 / `#d9b96a` 金 / `#26221c` 正文），深色 = 夜樱紫；窗口右上角常驻圆形主题 toggle（自绘太阳/月亮），初稿两套分别输出在 `light/`、`dark/`。座次色沿用 CLI 语义：黄/青/紫/红（浅色版加深适配）。卡组列表与卡组编辑支持**左右拖动翻页**（按钮 ‹ › 兜底）；查看/选择单卡的界面（编辑、式神录）**每页 5 卡**（原版亦如此）。

### 卡组构筑当前实现

- 退出构筑后重新进入一律回到卡组管理列表；未保存修改先询问保存、放弃或取消。点击编辑直接进入卡组，不额外弹卡组码。
- 卡组名统一固定两行并顶端对齐，超长部分裁切、悬停显示全名。式神选择的式神名列加宽并减少缩进。
- 阵容头像为 96×96px；卡页首位放置该基础式神卡供参考，不参与带卡数量与加减；普通卡每页 5 张、不额外套外框，底部按 `[-] 已选 x/2 [+]` 排列。五卡按等宽列铺满可用区域，末页按同列宽左对齐；卡图随实际列宽按原生尺寸等比重绘，不裁切。查看详情不显示构筑计数。进入编辑、切换式神/环境与翻页时显示真实耗时的加载提示，逐卡恢复事件处理，完成后自动关闭。

### 式神录当前实现

- 总览支持环境、版本包、派系与全名筛选，未发布/WIP 条目与构筑池一致排除；左侧为“版本包→式神”可折叠树，减少层级缩进并以整行浅蓝底标记选中式神；右侧显示选中式神的基础式神卡，点击该卡才进入其卡牌列表。
- 卡牌列表不再重复显示上方立绘、身材和能力信息，只保留返回栏、式神名、等宽五卡浏览区与翻页栏。专属与协战卡牌每页 5 张，首位基础式神卡仅查看，点击打开单卡详情。加载文本按真实耗时更新，浅深主题与主菜单返回行为同其他页面。传记、熟练度、合成/分解、异画替换与批量分解不做。

### 对局界面当前实现（2026-10，区别于上述初稿）

- **场景与布局**：本地热坐与联机对局共用 1600×900 逻辑坐标的 `QGraphicsScene/QGraphicsView`，窗口缩放保持比例，主窗口四周统一 12px padding。始终己下敌上；切换当前行动/作答方时复用同一组式神图元并交换上下半场，不另设顶部座位行或式神座位序号。准备区使用 148×210px 图元、横坐标 400+190×座次与 `24, 0, 0, 24` 弧线错位；进入战斗的既有图元移至中央上/下战斗位置，离战返回准备区。双方牌手贴近左上和左下角，显示圆形头像、右下生命图标与数值、鬼火、出击和带描边的鼓舞文字；幻境与墓地数量只在牌手详情显示。退出按钮位于主窗口顶栏、主题按钮左侧且不与敌方手牌重叠；右侧为双方上下镜像的三张横置斜叠牌库卡背（112×80px，空牌库不显示），牌库数量文本独立置于卡背组右侧；104px 圆形结束回合按钮以低对比背景、边框和文字明确区分禁用态，左中为战斗记录。`调度阶段 / 升级阶段 / 主要阶段` 以较小字号紧跟回合文本右侧，不再居中覆盖场况。
- **双方手牌**：手牌为 110×156px 图元，分别在右上/右下排列并右侧对齐；多张时横向重叠且位于式神上层，12 张允许遮住部分式神，不使用滚动区。常态己方按所属式神座次、等级、卡牌 id、`hand_seq` 依次排序，中立牌在最后；敌方与调度仍按 `hand_seq`，显示排序不改写底层入手记录。当前视角手牌显示正面；敌方未展示手牌只画占位卡背，`mods["revealed"]` 为真的实例在原顺序位置显示真实卡面，其他实例不附带卡牌定义。手牌与牌库提示使用主题正文色和 600 字重。可出击式神与单一合法付费方式显示黄色轮廓光，单一合法零鬼火方式显示蓝色轮廓光，实际合法子选项数大于 1 才显示绿色轮廓光；不合法牌不显示光效，颜色与合法性均读取当前 `usage_options`。
- **卡面与常态信息**：手牌与详情卡面通过 DIY 普通卡牌管线合成；对局中的基础/觉醒式神及形态统一通过 BWPDIY `render_entity` 小卡管线绘制，按实际 0–3 级、座次颜色及当前力量/战力/生命/护甲传参（0 级仅绘制底框与卡图，不绘制等级或任何数值角标）；适配层按原图比例与偏移计算最小覆盖缩放，保证卡图填满内窗且不露出框内黑边。各调用点传入原生 `height`（构筑/式神录按实际可用区域等比计算，手牌 156、调度 255、式神小卡 210、详情主卡 336、头像 96），尺寸进入缓存键，不对成品二次重采样。缺配置或正式插画时仍绘制完整卡框与文本，插画区域透明，成对花括号不进入卡面描述。所有场景卡面在槽位上限内保持合成图长宽比，右侧手牌按实际宽度对齐；等级勾玉按准备区座次使用 `yellow/cyan/purple/red`，无座次默认黄色。式神卡不再额外叠加力量/生命文字条，只有渲染器失败才回退文字/彩色框。
- **焦点与拖拽**：升级阶段由回合文本右侧标签提示，合法升级式神上方显示目标等级的座次色勾玉，其他画面由带孔洞的暗色遮罩压暗；拖拽出击/用牌时仅源卡、合法目标（含牌手）和箭头保持高亮，操作色使用卡图 alpha/轮廓掩码生成加粗渐变外光，不回退矩形 tight box。非追猎式神拖出源图元范围后松开即提交默认目标出击，追猎式神必须落到合法敌方式神；无目标手牌拖出后使用，目标手牌拖到合法角色上使用。多种使用方式在场景中央按调度式 180×255 大卡并列展示全部 `usage_options`，不可用项降透明度并显示 `reason`，合法项按统一 `id` 提交并保留拖放目标，取消后手牌不变。原位或无效落点取消，点击图元查看详情，升级阶段点击可升级式神。`target2` 等后续目标沿用现有高亮点选流程。
- **战斗记录**：左侧中部"战斗记录"打开独立、非模态、默认隐藏且重复复用的日志窗；关闭窗口不清空记录，也不暂停 timeline 播放。仅显示已播放且当前查看方有权看到的条目，起始调度阶段过滤对手的调度张数。本地热坐由引擎 cmd/event/op `trace` 写入 `bwpro.battle` 运行日志；联机仅写服务端过滤后随 state 下发的 `trace`。两种模式的 timeline 均只用于局内显示，客户端不自行重建事件/op 日志。
- **非阻塞播放与动画**：timeline 在后台播放，播放期间仍可执行合法操作；待处理选择、热坐交接、终局与联机等待响应等既有门控不变。同一式神进出战斗区时以 180ms 线性位置动画从旧位置移到布局终点，新动画取代同图元旧动画。统一 `_emit_card_played` 为主动、响应与自动用牌追加仅含公开 `uid/card_id/player` 的 `k="a"` 条目，客户端不解析中文日志；双方用牌从同步前缓存的原手牌位置与卡图离开（无缓存回退到对应手牌区），翻转成画面左侧大卡，短暂停留后淡出，900ms 后移除，且不进入文字记录队列。初次渲染、视角切换、交接与重开不播放并清理动画，动画不改变输入门控。
- **调度与热坐隐私**：调度阶段显示当前视角的先后手，己方五张大卡在场景中央横排，仅当前未确认方的手牌正面可见，另一方仍只显示卡背。点击手牌将其选中并轻微放大，再点击跟随该卡正下方的"替换"按钮调度，"确认调度"位于结束回合左侧；拖拽不会直接换牌。查看方切换时先弹出模态"交接设备"确认窗，清空双方手牌图元、拖拽副本/箭头、目标选择、结算选择与动画并关闭日志，暂停 timeline；确认后才按新视角重绘并恢复播放，窗口关闭/取消不能绕过确认。第三次调度后先按旧视角展示换牌结果并弹出"调度次数已用完"，确认交接时才清空手牌。
- **加载反馈**：启动预热不显示模态遮罩，只在状态栏显示后台进度并于完成后清除；热坐开局、联机场况渲染、构筑与式神录逐卡渲染及后台空闲时的手动全量重建，仍以全屏背景/遮罩隐藏加载中的界面，只居中显示真实耗时（0.1s 精度）的加载文本。逐项恢复 Qt 事件处理但不提前推进联机 timeline，完成或异常均自动关闭，不额外制造等待。
- **统一弹窗**：卡组选择、结算选择、详情与交接均使用应用内 `QDialog`；标准按钮经 `polish_dialog_buttons` 统一中文文案、紧凑样式与最小尺寸，构筑提示/确认也经同一入口处理。
- **运行时详情**：当前视角手牌详情显示实时卡面及当前费用、数值、增强、关键字、委托、使用条件和各使用方式合法性；敌方已展示手牌仅显示静态详情。式神详情按**式神主卡、同尺寸形态（如有）、全部额外状态（如有）、机制说明（如有）**同排成列，无内容不留空列；第三、四列均为最大高度 336px 的独立滚动机制框。主卡未觉醒时使用基础身材，觉醒时使用基础身材加永久修正及觉醒名称/文本，不混入临时或战斗修正；形态卡只使用 `form_power/form_health` 基础值。额外状态仅保留非零护甲/破甲与能量、永久/临时/动态修正、关键字、攻击强化、免疫、眩晕、延迟能力与灵咒等运行时信息，不重复基础等级/身材、派系或主卡、觉醒、形态原文；秘密延迟目标仍按查看方过滤。第四列先保留主卡与形态机制，再按第三列文本首次出现顺序补充方括号机制，最后合并当前关键字并去重；灵咒原文只通过第三列参与提取，不再单列灵咒机制框。机制定义加载项目 `library/mechanisms/*.yaml` 的 `name/frame/text/badge/version_date`，正文与框顺序同步。对局与终局共用该只读详情，终局允许查看但不接受操作。**逐条增益来源账本仍未完成**，09 所设想的"每条增减益数值+来源实体"保留为后续目标。

### 视频补充的交互细节（gui_ref 四段内录）

- **阵容创建弹窗**：含"输入阵容码"页签+创建按钮（signin/t100），我们的新建/导入卡组码可复用同一弹窗。
- **式神录·式神详情**（codex/t060）：右侧简介面板（定位/特长/成绩/传记）；我们简化为"基础/觉醒能力文本+定位标签"，胜场/熟练度等收集统计不做。
- **对手动作公告**：对局中央偏上显示"对手正在选择卡牌放回牌库"等即时提示（battle/t072），仅公开信息、不泄露对手具体手牌。

- **升级**：对局主界面上可升级式神金框高亮，点击即升级（不弹窗）。
