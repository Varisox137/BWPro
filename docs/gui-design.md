# GUI 维护参考

桌面客户端使用 PySide6，入口为 `python -m client.gui`。本文只记录当前实现与维护边界；规则语义以 `docs/rules.md`、术语与字段口径以 `docs/terminology.md` 为准。

## 1. 渲染与缓存架构

- BWPro 运行时不启动 BWPDIY exe、FastAPI 或 Web 服务，只调用 `bwpdiy.render`。`client/gui/cardart.py` 负责卡牌与式神卡图，`client/gui/portrait.py` 负责阵容头像。渲染资源默认取项目 `assets/`，可用 `BWP_DIY_ROOT` 覆盖；人工标注默认只读项目 `library/`，可用 `BWP_DIY_LIBRARY` 覆盖；全局布局读取 `~/.bwpdiy/layout.json`。
- 配置按卡牌/式神 id（兼容名称）和合法 8 位 `version_date` 与引擎快照精确匹配，不以相邻日期代替。名称、类型、等级、稀有度、派系、身材和描述始终由当前引擎定义合成；项目配置只提供 artwork、portrait、layout、faction_style 与 frame_variant。
- 构筑、详情和热坐/联机手牌共用 `card_pixmap`；基础/觉醒式神及形态共用 `shikigami_pixmap`/`render_entity` 管线；头像使用 `render_portrait`。`hand_cards_info` 同源提供运行时中文数值段与结构化 `render`，实时 `display` 和可选 `description_suffix` 进入渲染负载及缓存键，不回写引擎定义。未被卡面角标覆盖的实时增强数值以“（伤害+2）”形式追加到右键详情描述末尾；已由战斗牌力量/护甲角标完整体现的增强不追加。
- 各调用点传入原生 `height`，尺寸进入缓存键，成品不做二次重采样。缺配置、版本不匹配或缺插画时仍合成完整卡框与文本，仅插画透明；只有渲染器自身失败才回退文字卡面或空头像，操作与详情仍可用。
- 静态大卡缓存到 `~/.bwpro/cardart/card-<id>@<平衡性版本>-<牌框>-h<高度>-<sha256>.png`；静态小卡使用 `entity-<id>-<牌框>-h<高度>-<sha256>.png`，不因平衡性版本额外生成文件。内容指纹覆盖规范化负载、实际 layout、配置、原图与渲染资源，同语义前缀的新缓存写入后清理旧指纹文件。头像只用内存 LRU，含实时 `display` 的变体使用 256 项有界内存缓存，不逐值写盘。manifest 写到 `~/.bwpro/cardart/manifest.json`，记录当前外观、资源指纹、合成时间和成功/失败/跳过统计；设置页确认“重新合成”会清空整个专用缓存目录（含旧版本嵌套残留）后重建。
- 启动预热在后台线程执行，只合成当前外观的大卡与式神小卡，不枚举牌框、不预热头像；渲染与磁盘读写使用线程安全的 `QImage`，仅在 GUI 调用边界转换并复用 `QPixmap`。状态栏进度经排队回调更新，页面交互与动画不被逐张渲染阻塞；后台活跃时禁止进入热坐/联机并弹窗提示，设置页不启动全量重建，关闭窗口使回调失效而不强制终止线程。失败项下次启动重试。
- 对局图元保存 render signature，签名未变就复用现有 pixmap。签名覆盖卡面数值与状态、运行时详情、牌框/卡背、尺寸、座次和主题；视角切换、场景 reset、主题切换显式失效，动画快照按事件定点失效。性能回归断言 renderer 调用次数，不使用墙钟阈值。

## 2. 构筑与式神录

- 卡组管理支持新建、导入/查看卡组码、编辑、重命名、删除，以及独立的数据环境与卡组规则选择。标准规则为 4 式神、各 8 卡、至多 2 派系等；自由规则仅校验环境可用性与归属，非法卡组可保存但按校验结果标记。退出编辑回到管理列表，未保存修改先询问保存、放弃或取消；点击编辑直接进入卡组。
- 编辑器左侧为四式神阵容，每名式神提供“换”与“删”按钮分别替换和移除。中央按所属式神浏览卡牌。卡页首位的基础式神卡只供参考，不计入 8 张带卡；普通卡每页 5 张、等宽铺满，末页左对齐，底部使用 `[-] 已选 x/2 [+]`。卡图按实际列宽等比重绘，查看详情不显示构筑计数。
- 式神录支持数据环境、中文版本包、派系和全名筛选，以“版本包→式神”折叠树选择条目；未发布与 WIP 条目按构筑池口径排除。数据环境列出全部平衡性快照，大版本显示“包名(8 位日期)”，其余显示日期。列表关闭 `autoScroll`，避免首次绘制时抢滚动并改变鼠标点击目标。
- 式神录卡牌列表保留返回栏、式神名、五卡浏览区和翻页栏，不重复显示上方立绘与能力。左键打开常规/琉璃/墨染/百炼牌框选择，点击原画放大并确认保存；右键打开单卡详情。非常规外观按卡牌 id 稀疏保存到 `~/.bwpro/card_appearance.json`，应用于大卡图，小卡不变。传记、熟练度、合成/分解、异画选择与批量分解不在当前实现内。

## 3. 对局布局与输入

- 本地热坐与联机共用 1600×900 逻辑坐标的 `QGraphicsScene/QGraphicsView`，窗口等比缩放，主窗口四周为 12px padding。始终己下敌上；热坐切换视角时复用式神图元并交换上下半场。准备区图元为 148×210px，横坐标 `(196, 421, 871, 1096)`，弧线错位为 `arc=(120, 86, 86, 120)`；进离战斗区移动同一图元，召唤物只占战斗区。
- 牌手位于左上和左下，显示头像、生命/护甲、鬼火、出击与鼓舞；负护甲使用 `stats/weak.png` 破甲大图标，正护甲使用 `stats/shield.png`，均保持原比例。鬼火最多显示 4 点，不显示超上限溢出计数。右侧为双方牌库卡背，牌库与手牌数量文本统一位于组件左侧；牌库使用统一中央牌体裁剪的竖向卡背（装饰性透明外延不影响尺寸），按参考顶边与 25°/40°/45° 方向计算三组矩形，以实际回合按钮中心为对称轴镜像双方位置，仅最终中心坐标取整，并保留统一水平偏移入口。空牌库保留顶位图元，并按是否疲劳燃血选择明/暗素材。结束回合按钮在对手回合不可交互，图标使用按钮完整尺寸，按钮字样合成上限为按钮尺寸的 60%。
- 双方手牌分别在右下/右上右对齐排列，多张时横向重叠并位于式神上层。常态己方按所属座次、等级、卡牌 id、`hand_seq` 排序，中立牌最后；敌方与调度保留 `hand_seq`，显示排序不改写底层记录。敌方暗手只显示卡背，`mods["revealed"]` 实例在原位置显示真实卡面。
- 手牌和式神均由 DIY 管线绘制运行时卡面。仅充能式神显示能量（含 0）；普通倒计时与能量可共存；气绝保留能量、隐藏普通倒计时并显示复活倒计时或永久气绝。0 级式神只绘制底框与卡图，不绘制等级、数值角标或状态组件。具有 `unyielding` 时叠加 `misc/unyielding.png`，按非透明紧边界等比覆盖小卡中心，并将该状态纳入缓存身份。
- 可出击式神与合法用牌显示轮廓光：单一合法付费方式为黄色，单一合法零鬼火方式为蓝色，实际合法子选项多于一个为绿色，不合法项无光效；合法性读取当前 `usage_options`。
- 非追猎式神拖出源图元范围即提交默认目标出击，追猎必须落到合法敌方式神；无目标手牌拖出后使用，目标手牌拖到合法角色。多种使用方式以 180×255 大卡并列展示全部选项，每个爆能选项按实际爆能值分别调用 DIY 卡图渲染（含折扣后的 0 与爆能 X 的当前能量），不再另写爆能/鬼火/能量消耗文字，不可用项仅保留原因；合法项按统一 `id` 提交并保留拖放目标。`target2` 等后续目标使用高亮点选。原位或无效落点取消，右键查看详情。
- 升级阶段由双行回合/阶段标签提示，可升级式神显示目标等级勾玉，其余画面由带孔洞的遮罩压暗。文字 timeline 和主要阶段动画不阻塞合法操作；升级阶段在视觉队列非空时锁定输入并暂时隐藏升级焦点，队列排空后恢复。
- 调度只让当前未确认方看到正面手牌，另一方仍为卡背。中央五张大卡点击选中并放大，再点“替换”；确认后或用满三次后进入热坐交接。卡牌类 `pending_choice` 共用横向卡图选择视图，保留原始 uid/choice 映射；必答选择不可取消，联机等待 state 时不重复提交，重连按服务端 pending 恢复。
- 联机复用同一对局视图，仅指令传输、state 推送、回合倒计时和房间流程不同。默认服务器输入为 `bwpro.varisox137.top`；创建/加入/准备等按钮使用固定紧凑尺寸。数据环境与卡组规则独立：自选日期必须显式输入环境，卡组规则可选标准或自由。热坐同样提供这两个选项及 DIY 开关；仅符合当前规则的卡组进入候选。加载遮罩只在首次进入或重连时出现，后续 state 增量推送不遮挡棋盘。返回主菜单只暂停界面计时器，保留 WebSocket、房间状态和当前联机子页面；再次进入恢复当前房间/大厅/对局页面。离开房间只释放座位并保持服务器连接，同一连接可继续创建/加入。正式开局时服务端仅向本人下发 8 位识别码，意外断线后客户端经 ipify（备用 ifconfig.me）查询公网 IP，并以房码、识别码和入座时的公网 IP 自动重连；准备与开始倒计时阶段不启用该通道。
- 战斗记录是默认隐藏的独立非模态窗口，只显示已播放且当前查看方可见的条目；本地使用引擎 trace，联机只使用服务端过滤后下发的 trace，客户端不从动画重建私有日志。

## 4. 动画与热坐交接

- 移动、用牌与视觉事件进入全局动画队列，默认 FIFO；只有同一并行效果组且不同目标的动画可同时播放。视觉事件清单和快照字段见 `docs/rules.md`「视觉事件与呈现快照」，客户端不解析中文日志推断结算。
- `stat/countdown/countdown_proc/revive/defeated` 及气绝回位 `move` 在对应事件开始时应用快照 `r`；待播事件及视觉队列非空时延迟实时卡图刷新，排空后兜底同步。同效果单元内同目标且相邻的 `stat` 合并，不同目标只共享组号。法术觉醒的永久身材 stat 带视觉来源标记，播放前合并为同一最终快照并移到对应用牌动画之后，保证卡图、力量、生命同批刷新且先于卡牌效果；引擎结算顺序不变。
- 并行伤害/治疗按“前置护甲刷新→并行数字→并行生命刷新→并行气绝→并行回位”分阶段播放。`immune` 继承所属伤害事件的并行组 `g`，与同批伤害或其他免疫并行播放。正伤害首次被降为 0 的纯视觉事件显示 `-0`；原始 0、免疫、取消、转移和转化不显示该事件。
- 式神进出战斗区使用 180ms 线性位移动画。用牌从同步前缓存的原手牌位置与卡图离开，翻转为一侧大卡，停留并淡出后移除；响应先显示“响应”字样，再播用牌与效果动画。运势按骰点、重投（如有）、新骰点、结果逐段播放，双方同时判定时按同组呈现。
- 开局先展示双方玩家名/头像与已随机化的四式神顺序，中央使用 `battle_preview.png`；随后分别在双方空位以 70% 大小显示实际 `going_first/going_second`，中央按当前视角以原尺寸显示 `youre_first/youre_second`。阵容段依次为渐现 500ms、保持 1500ms、战字渐现 300ms、保持 1200ms、整体渐隐 500ms；先后手段依次为渐现 500ms、保持 1000ms、视角字样渐现 500ms、保持 1000ms、整体渐隐 500ms。由可取消的重复计时器推进，不改写对局状态；视口按 `sceneRect` 显式裁剪，越界牌库、按钮与加载前图元不绘制到两侧留白。
- 热坐回合开始以 `turn_start` 为边界两段播放：边界前条目留在旧视角，边界及之后条目暂存；视觉与移动队列全部排空后才显示交接按钮。确认新视角后重放暂存条目，再显示新视角回合横幅与战斗区退回动画。
- 回合结束已导致引擎切换行动方时，交接确认前仍保留刚结束回合玩家的回合/阶段标签；确认移交并切换 GUI 视角后才刷新。第三次调度仍先保留旧视角换牌结果，再经“隐藏手牌→切换玩家”两次点击交接；普通回合结束立即隐藏手牌，只需一次交接点击。终局不额外插入交接。
- 致死伤害及其视觉队列播放期间隐藏胜负横幅和返回按钮，队列排空后显示；`winner=None` 的玩家离开等结果仍立即显示。终局可查看只读详情，但不接受对局操作。

## 5. 详情与设置

- 卡牌、式神和牌手详情的同排栏目统一使用 `DETAIL_COLUMN_SPACING = 12`，即 12px 栏间距。应用内 `QDialog` 的标准按钮经 `polish_dialog_buttons` 统一中文文案、紧凑样式和最小尺寸；热坐交接使用场景内按钮。
- 当前视角手牌详情显示实时卡面、当前费用、数值、增强、关键字、委托、使用条件和各方式合法性；敌方已展示手牌只显示静态详情。
- 式神详情依次放置主卡、同尺寸形态（如有）、卡牌赋予的能力（如有）、机制说明（如有），无内容不留空列，所有栏目顶部对齐。后两列是固定高度 512px 的独立滚动机制框，与大卡图底部对齐，仅内容超高时出现纵向滚动；机制定义读取 `library/mechanisms/*.yaml`。觉醒主卡采用基础身材加永久修正，形态采用自身基础身材；额外状态只保留延迟能力、灵咒与眩晕，秘密目标按查看方过滤。逐条增益来源账本尚未实现。
- 山兔与三目的基础/觉醒详情通过 `description_suffix` 在描述末尾分别追加“（本局游戏已投出x次6点）”和“（本局游戏已完成x次委托）”，缺省计数为 0；后缀进入缓存键，不改写卡牌定义。
- 牌手详情仅横向展示幻境队列和当前可见的牌手级 aura/delayed 能力，不再重复生命、鬼火、出击或墓地摘要。幻境卡图高 512px并显示当前耐久，可右键打开单卡详情；空队列不留空列，宽度按实际列数计算，单幻境不保留固定 520px 空白；幻境与能力皆空时右键不打开详情。秘密延迟能力只向持有方显示。
- 游戏设置支持改名，并实时应用己方卡背、回合按钮底图与样式、升级和气绝样式，均提供预览。设置页可导入 JSON/ZIP DIY 包或清除外部获取内容，联机下载也会触发同一全局刷新；导入与下载后，式神录、构筑、热坐和联机立即可用这些内容。联机页不再单独输入玩家名；创建/加入时上报己方卡背并将其作为本次入座快照，对局中修改本地设置不影响对手视角，重连不刷新，下一次新 join 才更新。服务端在普通广播与重连 state 中回传对手卡背，仅作运行时覆盖且不写入本地设置。全部设置保存到 `~/.bwpro/gui.json`；卡背默认「月明风清」，按钮字样默认 golden，底图默认无。卡组、外观、卡图缓存与 GUI 设置分别使用各自文件，不混入引擎状态。
- 设置页提供“操作说明”只读弹窗。`notices.py` 集中维护操作说明与各版本更新内容；主窗口启动时比较当前版本与 `gui.json` 的 `last_started_version`，仅在当前版本高于本机已启动最高版本时展示“最近更新”，关闭后记录当前版本，重复启动或运行旧版本不重复弹出。

## 6. 独立日志运维端

- `python -m client.log_admin`（开发环境可运行 `uv run python -m client.log_admin`）启动独立于主游戏客户端的 PySide6 窗口，不加载卡牌数据库、卡图或对局界面。Termux 服务端只提供 HTTP API，不需要安装 GUI 依赖。
- 首屏输入服务器 HTTP(S) 地址与当前提取码。Termux 服务端项目目录下用 `cat logs/.log-access-token` 获取提取码；提取码启动时生成并每 30 分钟轮换，旧码随轮换失效。新码直接显示在交互控制台，但不写入应用日志或 launcher 的 `tee` 日志；无交互控制台时只提示文件路径。
- 连接后列表显示文件名、修改时间、大小和当前日志标记；单击日志只读预览开头最多 512 KiB，支持多选下载到本地目录。JSON 响应按实际读取限制为 2 MiB，下载按实际计数限制为 2 GiB-1，超限中断并删除半成品。请求在后台线程执行，鉴权、网络和文件失效错误显示在状态栏。
- 裸地址仅 loopback（`127.0.0.1`、`localhost`、`::1`）默认 HTTP，其他地址含带端口形式均默认 HTTPS；显式 HTTP 只兼容受信私网，公网必须通过 HTTPS 映射或反向代理，避免明文传输提取码和日志。运维端不提供远程删除、清空或实时 tail，主客户端联机页也不提供入口。

## 7. 发布与测试

- Windows 独立构建命令：`PYTHONIOENCODING=utf-8 ./.venv/Scripts/python.exe scripts/build_exe.py`。PyInstaller onefile/windowed 包内嵌规则、数据库、`assets/`、`library/` 与 BWPDIY 渲染代码，输出 `releases/BWPro-v<版本>.exe` 和 SHA-256；构建与冒烟成功后清理旧产物，每个二级版本仅保留最新补丁，且最多保留最近 5 个二级版本（EXE 与对应 SHA-256 一并清理）。GitHub Release 同样只保留每个二级版本的最新三级版本，发布新版本后删除同二级版本的旧 Release。冻结版从 `sys._MEIPASS` 读取内置资源，全局布局仍读 `~/.bwpdiy/layout.json`。
- 主窗口启动时自动检查更新，设置页也可手动检查；发现更高版本并经用户确认后，通过 HTTPS 下载与标签严格同名的 EXE/SHA-256 资产并校验内容。冻结版再次确认后退出主程序，由外部更新流程等待、替换并重启；开发环境只下载到 `~/.bwpro/downloads/`，不替换或重启当前程序。关闭窗口会使尚未返回的更新回调失效，取消或失败会清理半成品。
- 构建默认以隔离 HOME 运行 `--smoke-test`，覆盖数据库加载、大卡/小卡/头像/机制框与主窗口启动。应用与任务栏使用 `assets/app_icon.ico`；开发环境启动前设置固定 Windows AppID `Varisox137.BWPro.Desktop`，冻结版不覆盖系统分配的 AppID，避免任务栏沿用失效的快捷方式/图标缓存而忽略窗口图标。冻结版日志写入 `~/.bwpro/logs/`，启动时保留最近 15 天内的应用与 launcher 日志各最多 10 份，Windows 权限命令使用 `CREATE_NO_WINDOW`，不弹出命令行窗口。
- GUI 测试使用 Qt offscreen 平台，并通过自动临时 HOME 隔离卡图、卡组和设置，覆盖主窗口、构筑、式神录、热坐、联机、卡图缓存、详情和动画。运行全量测试：`PYTHONIOENCODING=utf-8 QT_QPA_PLATFORM=offscreen ./.venv/Scripts/python.exe -m pytest -q`；数据或文本变更另跑 `PYTHONIOENCODING=utf-8 ./.venv/Scripts/python.exe -m db.validate`。
