# GUI 设计文档（调研结论 + 界面初稿）

> 前置阅读：`docs/gui-plan.md`（PySide6 桌面客户端已落地，后续迭代与维护说明）。
> 界面初稿图在 `docs/gui-mock/`（`generate.py` 生成，PIL 绘制，仅为布局示意）。

## 1. bwpemu 调研结论（github.com/menghuanmus/bwpemu，v0.7.6）

**定位差异**：bwpemu 是纯手动沙盒模拟器——抽牌、鬼火增减、生命变动全靠玩家手动按钮，没有规则引擎。BWPro 是权威引擎路线（服务端结算、客户端只渲染+发指令），二者游戏逻辑层无可借鉴之处。

**技术形态**：纯静态单页（vanilla JS + GSAP + socket.io CDN），GitHub Pages 部署前端 + 独立 socket.io 后端，无构建步骤。仅作外部项目技术参考，BWPro 不采用其前端架构。

**可借鉴的 UX 模式**（桌面 GUI 可参考）：

- 大厅房间列表（免房码直接点入）、房间密码、复制房码按钮
- 观战模式、断线重连回房间
- 长按/悬停卡牌出 tooltip 大图与效果文本
- 骰子、卡牌飞行、眩晕等轻量特效（GSAP 补间即可，不必上游戏引擎）
- 结算记录 undo（仅沙盒有意义；我们引擎是权威结算，不做）
- 单人练习模式（对我们的价值：热坐已覆盖，优先级低）
- 移动端适配（media query 缩放布局；我们桌面优先，后期再说）
- DIY 卡库：容量上限、对局自动同步、选择性导入导出——与我们 Phase 3 + BWPDIY 联动时的参考

## 2. BWPDIY 卡图渲染工具接入（已落地）

**架构红线**：BWPro 运行时不启动、不依赖 BWPDIY exe、FastAPI 或 web 服务，只 `import bwpdiy.render`。BWPDIY exe 仅用于人工标注项目配置与原图，不参与构筑、对局或自动合成调用。

接入点：

1. **`client/gui/portrait.py`**：卡组列表复用 `bwpdiy.render.duo.render_portrait` 绘制带斜方框与派系标的式神头像。BWPDIY 仓库默认 BWPro 同级 `BWPDIY`，可用 `BWP_DIY_ROOT` 覆盖；项目配置库默认 **BWPro 项目内 `library/`**，可用 `BWP_DIY_LIBRARY` 覆盖，运行时只读。
2. **`client/gui/cardart.py`**：从 `library/<项目>/{shikigami,cards}/*.yaml` 读取人工标注，按 id（兼容名称）与引擎定义的版本快照日期精确匹配 `version_date`；配置日期必须是合法 8 位日期，不用相邻日期代替。卡牌的名称、类型、等级、稀有度、所属式神、派系、身材与描述等显示数据始终由当前引擎定义合成，项目配置只提供 artwork、portrait、layout 与 faction_style，不让旧配置文本或数值覆盖引擎数据。
3. **共用卡面**：构筑卡面、静态/运行时卡牌详情、热坐与联机手牌均调用同一 `card_pixmap`。`hand_cards_info` 同源生成中文数值段与结构化 `render`，战斗、形态、觉醒等实时身材经 `display` 注入卡面负载和缓存键，不修改引擎定义；费用、增强计数、关键字、使用条件等仍由 GUI 详情层显示。
4. **Phase 3 DIY 联动**：BWPro `diy/` 只读消费 BWPDIY `library/<项目>/` 下的式神/卡牌 yaml——"BWPDIY 做卡、BWPro 打牌"。映射层（BWPDIY yaml → BWPro yaml 口径）只放在 `diy/` 一处。

静态全卡 PNG 默认缓存到 `~/.bwpro/cardart/<sha256>.png`；含实时 `display` 的变体仅使用 256 项有界内存缓存，不逐值永久写盘。缓存键包含规范化引擎负载、合并后的实际 layout、配置 YAML 内容 SHA-256、原图 `mtime_ns` 与 size、BWPDIY 版本及渲染资源根；layout 另有 64 个元素、512px 元素尺寸的渲染预算。缺配置、版本不匹配或缺图时仍调用 DIY 渲染完整卡框与文本，仅插画区域透明；只有渲染器自身失败才回退文字卡面。头像回退带斜方框和派系标的空槽（不绘制人物），操作按钮与运行时详情保持可用。

## 3. 界面初稿（docs/gui-mock/，1600×900）

布局参照原版游戏截图与内录视频抽帧（`gui_ref/`，版权原因不入库）。**美术定位：2D 平面布局**——原版对局是 3D 场景（斜俯视牌桌、式神 3D 模型），我们不复刻，只保留其信息层级与版式（上下半场、四角头像、扇形手牌等），卡牌/式神一律 2D 卡面占位。**双主题可切换**：浅色 = BWPDIY 羊皮纸（`#f3efe8` 纸底 / `#fffbe9` 面板 / `#d9b96a` 金 / `#26221c` 正文），深色 = 夜樱紫；窗口右上角常驻圆形主题 toggle（自绘太阳/月亮），初稿两套分别输出在 `light/`、`dark/`。座次色沿用 CLI 语义：黄/青/紫/红（浅色版加深适配）。卡组列表与卡组编辑支持**左右拖动翻页**（按钮 ‹ › 兜底）；查看/选择单卡的界面（编辑、式神录）**每页 5 卡**（原版亦如此）。

### 卡组构筑当前实现

- 退出构筑后重新进入一律回到卡组管理列表；未保存修改先询问保存、放弃或取消。点击编辑直接进入卡组，不额外弹卡组码。
- 卡组名统一固定两行并顶端对齐，超长部分裁切、悬停显示全名。式神选择的式神名列加宽并减少缩进。
- 阵容头像为 88×88px；卡页首位放置该基础式神卡供参考，不参与带卡数量与加减；普通卡每页 5 张、不额外套外框，底部按 `[-] 已选 x/2 [+]` 排列。查看详情不显示构筑计数。进入编辑、切换式神/环境与翻页时显示真实耗时的加载提示，逐卡恢复事件处理，完成后自动关闭。

### 对局界面当前实现（2026-10，区别于上述初稿）

- **场景与布局**：本地热坐与联机对局共用 1600×900 逻辑坐标的 `QGraphicsScene/QGraphicsView`，窗口缩放保持比例，主窗口四周统一 12px padding。始终己下敌上；切换当前行动/作答方时复用同一组式神图元并交换上下半场，不另设顶部座位行或式神座位序号。准备区使用 148×210px 图元、横坐标 400+190×座次与 `24, 0, 0, 24` 弧线错位；进入战斗的既有图元移至中央上/下战斗位置，离战返回准备区。双方牌手贴近左上和左下角，显示圆形头像、右下生命图标与数值、鬼火、出击和带描边的鼓舞文字；幻境与墓地数量只在牌手详情显示。退出按钮位于场景右上、主题按钮左侧；右侧为三张斜叠牌库卡背（空牌库不显示）、104px 圆形结束回合按钮和己方牌库，左中为战斗记录。
- **双方手牌**：手牌为 110×156px 图元，分别在右上/右下排列并右侧对齐；多张时横向重叠且位于式神上层，12 张允许遮住部分式神，不使用滚动区。常态己方按所属式神座次、等级、卡牌 id、`hand_seq` 依次排序，中立牌在最后；敌方与调度仍按 `hand_seq`，显示排序不改写底层入手记录。当前视角手牌显示正面；敌方未展示手牌只画占位卡背，`mods["revealed"]` 为真的实例在原顺序位置显示真实卡面，其他实例不附带卡牌定义。手牌与牌库提示使用主题正文色和 600 字重，己方手牌不绘制蓝色可操作方框。
- **卡面与常态信息**：手牌与详情卡面通过 DIY 普通卡牌管线合成；对局中的基础/觉醒式神及形态统一通过 BWPDIY `render_entity` 小卡管线绘制，按实际 0–3 级、座次颜色及当前力量/战力/生命/护甲传参。各调用点传入原生 `height`（构筑 360、手牌 156、调度 255、式神小卡 210、详情主卡 336、头像 88），尺寸进入缓存键，不对成品二次重采样。缺配置或正式插画时仍绘制完整卡框与文本，插画区域透明，成对花括号不进入卡面描述。所有场景卡面在槽位上限内保持合成图长宽比，右侧手牌按实际宽度对齐；等级勾玉按准备区座次使用 `yellow/cyan/purple/red`，无座次默认黄色。式神卡不再额外叠加力量/生命文字条，只有渲染器失败才回退文字/彩色框。
- **焦点与拖拽**：升级阶段中央高亮"升级阶段"，合法升级式神上方显示目标等级的座次色勾玉，其他画面由带孔洞的暗色遮罩压暗；拖拽出击/用牌时仅源卡、合法目标（含牌手）和箭头保持高亮，源卡不再额外降透明度。非追猎式神拖出源图元范围后松开即提交默认目标出击，追猎式神必须落到合法敌方式神；无目标手牌拖出后使用，目标手牌拖到合法角色上使用，多种使用方式在松开后经现有弹窗确认。原位或无效落点取消，点击图元查看详情，升级阶段点击可升级式神。`target2` 等后续目标沿用现有高亮点选流程。
- **战斗记录**：左侧中部"战斗记录"打开独立、非模态、默认隐藏且重复复用的日志窗；关闭窗口不清空记录，也不暂停 timeline 播放。仅显示已播放且当前查看方有权看到的条目，起始调度阶段过滤对手的调度张数。
- **调度与热坐隐私**：调度阶段显示当前视角的先后手，己方五张大卡在场景中央横排，仅当前未确认方的手牌正面可见，另一方仍只显示卡背。点击手牌将其选中并轻微放大，再点击画面中央"替换"按钮调度，"确认调度"位于结束回合左侧；拖拽不会直接换牌。查看方切换时先弹出模态"交接设备"确认窗，清空双方手牌图元、拖拽副本/箭头、目标选择与结算选择并关闭日志，暂停 timeline；确认后才按新视角重绘并恢复播放，窗口关闭/取消不能绕过确认。第三次调度后先按旧视角展示换牌结果并弹出"调度次数已用完"，确认交接时才清空手牌。
- **加载反馈**：热坐开局、联机场况渲染与构筑逐卡渲染期间，中央显示真实耗时（0.1s 精度）的加载文本；逐卡恢复 Qt 事件处理但不提前推进联机 timeline，完成或异常均自动关闭，不额外制造等待。
- **统一弹窗**：卡组选择、使用方式、结算选择、详情与交接均使用应用内 `QDialog`；标准按钮经 `polish_dialog_buttons` 统一中文文案、紧凑样式与最小尺寸，构筑提示/确认也经同一入口处理。
- **运行时详情**：当前视角手牌详情显示实时卡面及当前费用、数值、增强、关键字、委托、使用条件和各使用方式合法性；敌方已展示手牌仅显示静态详情。式神主卡未觉醒时使用基础身材，觉醒时使用基础身材加永久修正及觉醒名称/文本，不混入临时或战斗修正；并列形态卡只使用 `form_power/form_health` 基础值。下方状态区继续显示当前生命、永久/临时/战斗修正汇总、形态、觉醒、延迟能力与灵咒等；**逐条增益来源账本仍未完成**，09 所设想的"每条增减益数值+来源实体"保留为后续目标。
