# BWPDIY 集成适配收尾设计

日期：2026-10-30

## 目标

落实 BWPDIY 最新集成报告中仍未覆盖的适配项，保证 worktree 可用、失败可诊断、缓存状态可信，并补齐新渲染数据字段。BWPDIY 四个渲染入口 API 不变，不修改对方源码。

## 资源根与日志

- `BWP_DIY_ROOT` 始终优先；未配置时从当前文件向上寻找具有同级 `BWPDIY/assets` 的项目根，不再固定 `parents[3]`。
- 大卡、小卡、头像、机制框和 YAML 配置解析失败记录渲染类型、id/名称、资源根、配置路径与异常堆栈。
- 相同失败按“类型 + id + 资源根”有界去重，防止每次刷新刷屏；清理卡图缓存时同步清理去重状态。
- 磁盘读写失败与渲染失败使用不同日志文案。透明插画牌框和空头像槽是合法产品结果，不记为异常。

## 渲染字段与缓存

- 大卡配置的 `frame_variant` 同时进入渲染负载和 `get_type_layout`；小卡也传入对应字段，继续参与现有负载缓存键。
- 机制 `badge` 进入 `render_mechanism` 负载和 LRU 键；仅 `seal` 使用 `bless/eclipse` 的既有约束不变。
- 运行时大卡和小卡 LRU 与静态路线一致，只缓存成功 pixmap，`None` 可在同进程立即重试。
- 预热全量跳过时记录 skipped；失败项记录 kind/id/version/reason。设置页显示成功、失败、跳过数量、失败摘要和 manifest 路径。
- 保留现有成功 entries 返回契约，不改回“返回全部期望条目”。

## 文档同步

更新 `docs/bwpdiy-integration.md`、`docs/gui-design.md` 与必要的集成说明：

- 缓存身份是渲染实现指纹，不是 BWPDIY 版本号。
- 头像只有内存 LRU，没有磁盘缓存；启动预热当前只处理大卡和小卡。
- editable 安装只解决 Python 导入，资源根仍需正确配置。
- 合法透明占位与异常回退必须区分。

## 验证

覆盖 worktree 根推导与环境变量优先级、日志去重、frame_variant 布局选择、badge 缓存隔离、运行时失败重试、预热统计与设置页显示。完成后运行相关 GUI 测试、默认 `-n 4` 全量测试；未改卡牌数据时无需 `db.validate`。
