# 对局规则边界与选择交互修正设计

日期：2026-10-30

## 目标

修正瞬发光环跨回合、山兔卡牌身份映射、热坐移交隐私，以及余辉/残阳无影的选择交互。原版卡牌描述继续以 `card_data_raw.md` 为唯一事实来源，不修改该文件。

## 瞬发光环回合边界

妖刀姬能力产生的 `card_aura` 使用 `scope="turn"`，其语义统一为所属半回合有效，在该半回合结束时清除，而不是延续到己方下一回合开始。见切在敌方回合响应时应重新按普通响应牌支付鬼火；觉醒版 `cost_zero` 同样遵守该边界。检查其他 `scope="turn"` 用法，确保没有依赖跨敌方回合残留的特例。

## 山兔数据修正

按 raw 修正 05–08：

- `10011705` 戏谑套索；
- `10011706` 来打我呀；
- `10011707` 萌即正义；
- `10011708` 这把算我赢，等级 3，基础关键字不含瞬发。

同步所有效果引用、测试常量与文档状态。卡图配置查询的测试同时校验 id 与 name，防止“任一匹配”掩盖身份错位。萌即正义不应使两张“这把算我赢”显示免费蓝边。

## 热坐移交

用完第三次调度后，复盘弹窗“调度完毕请确认”仍保留中央手牌供查看；进入“准备移交”时立即移除旧玩家手牌，确认后显示新玩家视角。补充双方 ready、首次升级、首回合结束的完整交接回归。首回合无弹窗在正常流程未复现，不引入未经证实的首回合特殊分支。

## 统一选择交互

- 余辉由随机弃牌改为 `discard_pick`，候选仅为当前手牌中的幻境牌；选择后弃置并继续抽三张，无合法候选时不挂起且仍抽三张。
- `discard_pick` 增加目标过滤参数，作答继续使用 uid；联机脱敏和超时随机作答沿用统一通道。
- 残阳无影的 `field_summon_pick` 与余辉弃牌共用卡图式中央候选视图；其他卡牌型 pending choice 可复用同一视图，式神/灵咒保留专用文本回退。
- 候选按卡牌横向排列，超出可用宽度时启用横向滚动。选择成功后关闭旧窗口并清理 `_choice_key`；连续 pending 才允许打开新窗口，不通过允许取消必答选择来“修复”关闭问题。

## 验证

覆盖见切跨回合耗火、觉醒同边界、山兔 id/name/等级/关键字与卡图、第三次调度移交隐私、首回合交接、余辉候选过滤/空候选/抽牌、残阳多候选与单候选、实际按钮关闭及联机回包。修改 yaml 后必须运行 `python -m db.validate`，最后运行默认 `-n 4` 全量测试。
