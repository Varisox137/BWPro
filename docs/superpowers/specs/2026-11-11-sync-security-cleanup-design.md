# 同步、局内计数、安全审查与低风险精简设计

## 目标与边界

纳入当前 `card_data_raw.md` 与 `library/` 全部改动，保持引擎 YAML、卡图配置描述和原始文本一致；补充山兔与三目的局内详情计数；完成安全审查及文档、代码、测试的低风险精简。不得修改 raw 内容，不改变既定规则行为，不进行引擎或 GUI 主模块重构。

## 数据与文本同步

- 将现有 raw 修订和 library 的全部修改、新增配置与图片纳入最终提交。
- 使用 `scripts/sync_library_text.py` 同步卡图描述；通过 `db.validate` 验证 engine YAML 的 text 与 raw 逐字一致。
- 检查同步结果的差异，避免格式化工具产生无关 YAML 重写。

## 局内详情计数

- 在式神详情渲染路径增加可选描述后缀，后缀进入渲染负载和缓存键，不改变基础式神/觉醒卡的其他字段。
- 山兔后缀：`（本局游戏已投出x次6点）`，读取所属牌手 `ext["dice_six_count"]`，缺省为 0。
- 三目后缀：`（本局游戏已完成x次委托）`，读取所属牌手 `quest_counts["quest_used"]`，缺省为 0；委托牌的 [条件] 或“视为达成”保证使用该牌即完成委托。
- 基础与觉醒详情均生效；覆盖计数递增、零值和缓存隔离测试。

## 热坐交接显示

- 回合结束导致引擎切换行动方后，左侧回合/阶段标签仍保留刚结束回合玩家的文本，直到确认移交并切换 GUI 视角。
- 交接动画边界、隐私隐藏和结束回合按钮逻辑不变；覆盖移交前、确认后的回归测试。

## 安全审查

检查服务端指令和大小限制、房间与重连令牌、状态脱敏、debug 开关、文件路径与原子写入、外部进程、日志敏感信息及依赖漏洞。高置信可复现问题直接修复并添加回归测试；其余记录为风险或既定信任边界，不引入新的认证体系或部署架构。

## 文档与实现精简

- 删除 `docs/superpowers/` 历史 specs/plans 和 `docs/gui-plan.md`，Git 历史作为追溯方式。
- 保留并压缩 `rules.md`、`terminology.md`、`card-status.md`、`gui-design.md` 等现行参考，删除过期行为描述和重复实现清单。
- 仅清理死代码、重复辅助逻辑及跨层重复测试；保留机制覆盖和负例，不按行数强行删减，不重组大型模块。

## 验证与提交

先运行受影响测试与文本同步检查，再运行完整 `pytest` 和 `db.validate`。复核安全修复、最终 diff 和删除清单后，将全部相关改动以中文 conventional commit 提交并推送。
