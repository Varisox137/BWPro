# 卡图缓存复用与后台预热设计

日期：2026-10-30

## 目标

避免 BWPDIY 仅更新版本号、WebGUI 或发布文件时，BWPro 启动仍从第一张卡开始重新渲染全部卡图。缓存复用以实际渲染输入是否变化为准；真正受渲染代码或资源变化影响的卡图在后台增量刷新，启动过程不阻塞主界面。

本轮不设计 BWPro exe 打包，也不引入自动更新功能。

## 根因

当前 `prewarm._manifest_current()` 比较 `renderer_version`，`cardart._card_cache_key()` 又写入 `bwpdiy_version`。因此任何 BWPDIY 版本号变化都会同时使预热清单和全部 PNG 缓存键失效，即使渲染代码、assets、卡牌配置与图片均未改变。

现有缓存键已经包含卡牌负载、有效布局、卡牌配置 SHA-256 和卡图内容 SHA-256，可以直接保留这些精确输入。

## 缓存兼容性口径

### 大卡

大卡缓存使用以下输入：

- 卡牌渲染负载；
- 有效布局与单卡配置摘要；
- 卡图内容 SHA-256；
- assets 内容摘要；
- BWPDIY 渲染源码内容摘要；
- 输出高度。

移除 `bwpdiy_version` 对缓存键的直接影响。`renderer_root` 仍用于定位当前渲染器，但不作为判断版本更新的替代品。

### 对局小卡

沿用现有“assets + render 源码”摘要，并继续包含实体 state、形态/觉醒来源、卡图与输出高度。版本号本身不再触发小卡全量失效。

### 失效范围

- 仅版本号、WebGUI、编辑器、发布说明变化：缓存全部复用。
- 普通大卡渲染源码或共享 assets 变化：大卡进入增量刷新；小卡是否刷新按其实际摘要判断。
- 对局小卡渲染源码或共享 assets 变化：小卡进入增量刷新。
- 卡牌定义、布局、配置或卡图变化：仅对应缓存项失效。

共享渲染源码按内容摘要判断。无法安全证明某次源码编辑只影响一种卡牌类型时，允许让该渲染类别整体刷新，不用版本号猜测兼容性。

## 后台预热

启动后先显示主窗口，再由 `QTimer` 分片调用现有预热逻辑。每次事件循环处理少量定义并立即让出控制权，保持按钮、页面切换和详情交互可用。

所有 `QPixmap` 仍在 GUI 线程创建和使用，不把 Qt 图元交给工作线程。共享的 BWPDIY 渲染锁保持现状。

- 有效缓存项只检查并跳过，不重新渲染。
- 失效项逐张生成新 PNG，旧文件保留到成功替换之前。
- 后台预热不使用模态全屏遮罩。
- 主窗口状态栏显示非模态进度“卡图后台同步 当前/总数”，完成后清除；失败时显示失败数量，详细原因写运行日志。
- 设置页“重新合成全部卡图资源”继续使用确认后的全量重建入口，不受后台任务重复触发；同一时刻只允许一个预热任务运行。

后台任务与按需渲染使用同一缓存键和原子写入逻辑。若用户先打开某张失效卡牌，按需路径可以先生成，后台随后命中同一缓存而不重复渲染。

## 清单与失败处理

预热清单移除 `renderer_version` 作为相等条件，改为比较大卡/小卡实际渲染摘要和全部定义条目。

只有实际返回非空 pixmap 的条目才计为成功。存在失败时：

- 不写入会跳过全部后续重试的完整成功清单；
- 已成功的 PNG 继续保留并可复用；
- 失败项在下一次启动或手动重试时继续参与渲染；
- 设置页显示成功、失败和跳过数量，不只按 entries 数量声称缓存已生成。

新缓存策略首次切换时，旧键中的版本号可能使部分已有 PNG 无法直接匹配，允许一次迁移性重建。此后版本号变化本身不再造成全量重建。

## 缓存维护

保留设置页清除并全量重建作为最终纠错入口。本轮不增加基于时间的自动清理或复杂旧键迁移；避免为消除一次迁移成本引入额外缓存别名。

## 验证

自动化测试覆盖：

1. 仅 BWPDIY 版本号变化时，缓存键不变且第二次预热不调用渲染器。
2. 仅 WebGUI/编辑器文件变化时，缓存键不变。
3. 渲染源码变化时，对应类别缓存键变化并进入增量刷新。
4. 卡牌定义、布局或卡图变化只使对应项失效。
5. 后台分片执行期间 Qt 事件循环可处理其他交互，完成后写出清单并清除进度。
6. 重复启动、手动重建与后台任务不会并发写入同一预热任务。
7. 渲染失败不形成完整成功清单，下次启动会重试，已成功 PNG 保留。
8. 相关 GUI 测试与默认 `-n 4` 全量测试通过。
