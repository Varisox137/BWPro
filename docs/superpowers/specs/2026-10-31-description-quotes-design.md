# 卡牌描述引号与具名内容高亮设计

日期：2026-10-31

## 目标

统一卡牌描述中的引号样式，并在 DIY 卡图渲染时对引号内的具名卡牌、衍生物和灵咒进行关键字高亮。文本数据与渲染标记分离，不改变卡牌效果或平衡性数据。

## 数据迁移

本次按用户明确要求修改 `card_data_raw.md`，仅进行引号迁移，保留文件内其他现有修订：

- 外层 `‘…’` 改为 `『…』`；
- 当前唯一嵌套的 `“棺材”` 改为 `「棺材」`；
- 同步所有 DB YAML 的历史版本 `text` 与 `methods[].text`；
- 不修改 library 中的 DIY 配置、卡图或布局。

raw 与 YAML 不写入 `[[…]]`。`db.validate` 继续逐字比较，不增加引号规范化豁免。更新 rawtext 示例、受影响测试和术语文档。

## 渲染高亮

`client/gui/cardart._description` 增加数据库感知的具名内容处理，实际调用点传入当前环境 db。名称集合包括：

- 全部 `db.cards` 名称；
- `db.shikigami` 中召唤、变形、替换等非普通式神实体名称；
- 全部 `db.invocations` 名称；
- token 卡名中 `·` 前缀族，用于统称引用。

只对 `「…」` 或 `『…』` 的完整内容命中名称集合的部分包裹 `[[…]]`。整段能力文本、未知名称和已经带 `[[…]]` 的内容不重复包裹；现有 `[关键字]` 与 `#xx` 图标转换保持原顺序。BWPDIY 继续负责剥离 `[[…]]` 并异色，无需修改其渲染器。

示例：

```text
将一张『[[黄金羽]]』置入手牌。
使一个非召唤物式神获得『本回合气绝时，替换为「[[棺材]]」』。
```

## 验证

覆盖普通衍生牌、灵咒、衍生物、token 族统称、嵌套棺材、普通关键字、非名称长文本及防重复包裹。增加旧单引号清零与角括号配对检查，运行受影响测试、默认 `-n 4` 全量测试和 `python -m db.validate`。
