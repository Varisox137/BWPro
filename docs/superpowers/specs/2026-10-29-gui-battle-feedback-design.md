# GUI 对局反馈与详情修正设计

日期：2026-10-29

## 目标

修正热坐试玩发现的八项 GUI 问题，同时保证本地热坐与联机共用状态渲染、详情和终局交互口径。采用现有渲染与状态链路上的定点修改，不重建 GUI view-model，不修改卡牌规则或联机协议。

## 1. 手牌动态数值颜色

`client/gui/cardart.py` 在静态卡牌数据生成实时 `display_stats` 覆盖后，比较实时值与当前环境版本的卡牌原始值：

- 小于原值：红色；
- 等于原值：白色；
- 大于原值：青色。

颜色写入 DIY 渲染负载的 `<field>_color`，沿用渲染器现有 `red`、默认白色、`green` 映射。颜色参与现有缓存键，不新增缓存结构。只改变显示，不回写引擎数值。

## 2. 式神小卡数值颜色基准

式神力量与生命上限的颜色基准统一为“当前基础值 + 永久值”：

- 无形态：式神基础值；
- 有形态：形态基础值；
- 永久值：沿用当前式神的永久修正。

力量继续按当前力量低于、等于、高于基准显示红、白、青。生命继续沿用既有规则：当前生命低于生命上限为红；未受伤时，生命上限小于等于基准为白，高于基准为青。气绝状态的显示值使用同一基准。

## 3. 对局页边距

仅对局页移除外层窗口边距，不改变主菜单、构筑和式神录的布局。`BattleScene` 继续保持等比缩放，不恢复拉伸或裁切；场景内既有贴边坐标保持不变。

## 4. 对局记录按钮

原生圆形“对局记录”按钮由 32×32 增至 40×40，圆角半径同步为 20px。保留现有非模态记录窗口、位置与主题样式，并以字体度量验证两行文字不溢出圆形轮廓。

## 5. 终局立即提示与只读交互

本地热坐和联机收到引擎终局状态后立即显示胜负，不等待 timeline 文字记录或动画队列清空；移除联机 `_pending_game_over` 的延迟展示路径。结果层 z-order 高于出牌动画。

终局后仍禁止升级、出击、用牌和结束回合，但允许：

- 打开、关闭对局记录；
- 点击牌手、式神、手牌查看详情；
- 操作结果提示自身的关闭或返回入口。

拖拽控制器将“点击查看详情”与“发起游戏操作”分开判断，不再用 `_inputs_open()` 一并拦截只读点击。

## 6. 牌手详情入口

删除独立“牌手详情”按钮及场景布局项。点击相应牌手的圆形头像区域打开详情；牌手为合法目标时，目标选择优先于详情。牌手头像之外的名称、数值等空白区域不触发详情。

## 7. 出牌动画卡图

动画大卡图的高度在调用 DIY 渲染前转换为正整数，避免浮点尺寸被渲染器拒绝。若大卡图渲染失败，保留动画已有的原手牌卡图作为回退，不用空 pixmap 覆盖；仅在原本就没有卡图的暗手牌阶段显示卡背。

## 8. 式神详情四列布局

详情上半部按实际内容从左到右排列：

1. 式神卡；
2. 形态卡（如有），与式神卡同尺寸；
3. 全部额外状态（如有）；
4. 机制说明（如有）。

无对应内容时不保留空列。各列自适应分配可用宽度，机制说明和额外状态内容累计高度超过卡面高度后，各自使用独立纵向滚动条。下方不再重复显示完整状态文本。

第三列使用机制框样式展示灵咒、额外/延迟能力、当前关键字、限时强化、眩晕、免疫及其他运行时状态。

第四列先按卡面文本顺序列出式神卡与形态卡涉及的机制，再按第三列文本首次出现顺序补充其中涉及的关键字/机制；全部按首次出现去重。机制正文继续读取项目 `library/mechanisms/*.yaml`，不新增硬编码机制正文来源。

## 数据流与兼容性

- 手牌与式神颜色均在 `cardart` 渲染负载层计算，本地和联机自然共用。
- 终局判断直接读取引擎/state 的终局字段，timeline 仅负责后续记录和动画展示。
- 详情从当前只读 state 提取数据，不产生游戏指令。
- 不修改引擎结算、卡牌数据、协议字段和卡组格式。

## 验证

为以下行为增加或更新 GUI 回归测试：

- 手牌三种数值颜色及缓存负载；
- 无形态/有形态、气绝/未气绝的式神颜色基准；
- 对局页外边距、40px 圆形记录按钮和文字边界；
- 本地与联机终局立即提示，以及终局后的记录和详情点击；
- 牌手头像点击与目标选择优先级；
- 双方出牌动画的大卡图非空及失败回退；
- 详情列顺序、无空列、同尺寸、机制去重与独立滚动。

迭代期运行相关 `tests/test_gui_*.py`，完成后运行默认 `-n 4` 全量测试。全量通过后再进行任务级和整分支代码审查。
