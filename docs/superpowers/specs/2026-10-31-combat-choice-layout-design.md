# 战斗牌交互、抽牌参数与对局边距修正设计

日期：2026-10-31

## 目标

修复余辉选择后引擎异常、战斗牌含交互效果的发起战斗时点，以及对局顶部按钮与手牌数量布局。保留现有 pending choice 协议和卡牌文本。

## 抽牌参数

余辉与蓬莱玉枝的后续抽牌统一使用 `draw count=3`，不再使用未注册的 `amount` 参数。回归测试使用真实 YAML 完成弃牌/召唤、抽三和 pending 清空；弹窗灰化只是异常中断症状，不新增关闭捷径或允许取消必答选择。

## 战斗牌效果时点

普通与交互效果均遵循“卡面效果全部完成 → 入墓与战斗替换 → 发起战斗相关时点”。`_resolve_combat_card` 遇到 pending choice 时，整个战斗后续一并挂起，而非仅挂起单个效果块。

作答后续完剩余效果，再统一入墓并发起一次战斗；外层出牌收尾与 `on_card_played` 不得重复。残阳无影因此先召唤幻境，再在攻击时检测己方幻境并获得先攻。先攻快照和其他战斗阶段逻辑不变。

## 顶部 chrome 边距

对局场景 outer 继续保持零边距，顶部 chrome 在对局中单独设置 `(12,12,12,0)`，非对局恢复 `(0,0,0,0)`。返回主菜单、构筑和联机连接页时，outer 与 chrome 均恢复主菜单口径，场景等比缩放不变。

## 手牌数量位置

- 敌方手牌 `(1530,156)`，位于敌方牌库 `(1530,228)` 上方；
- 己方手牌 `(1530,680)`，位于己方牌库 `(1530,608)` 下方；
- 两处手牌标签与牌库标签统一 `68×64`，垂直间距 8。

热坐与联机共用布局和文本构造，不涉及协议。

## 验证

覆盖真实余辉弃牌抽三与弹窗关闭、蓬莱玉枝参数、残阳无影先召唤后先攻且战斗仅一次、对局/非对局 chrome 与 outer 边距、手牌/牌库标签精确坐标和 8px 间距。修改 YAML 后运行 `db.validate`，最后运行默认 `-n 4` 全量测试。
