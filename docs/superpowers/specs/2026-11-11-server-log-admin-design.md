# 服务端详细日志与独立运维端设计

## 目标

让 Termux 等远程部署环境中的服务端日志可安全地浏览、预览和下载，并补全联机排障所需的连接、房间、玩家操作与引擎事件上下文。主游戏客户端不增加自动下载行为；日志管理由独立桌面程序承担。

## 服务端日志

- 沿用 `core/logging_config.py` 的 DEBUG 文件、异常堆栈及 7 天/10 份启动清理策略。
- 复用引擎 `bwpro.battle` 的指令与原子事件追踪，不另建结算日志系统。
- 补齐房间 ID、指令接受/拒绝、连接关闭码与原因、创建/加入/离开/重连及引擎异常上下文。
- 不在日志中记录完整重连令牌或日志提取码。

## 提取码与鉴权

- 服务端启动时以安全随机数生成 16 位小写十六进制提取码，此后每 30 分钟轮换；仅最新码有效。
- 当前提取码原子写入 `logs/.log-access-token`，权限限制为当前用户读写；该文件不属于可下载日志。
- 每次生成时通过交互终端设备直接显示提取码：POSIX 使用 `/dev/tty`，Windows 使用 `CON`。这样控制台可见，但应用日志和 Termux launcher 的 `tee` 均不会捕获它。无交互终端时仅提示提取码文件路径。
- 运维请求通过 `Authorization: Bearer <提取码>` 鉴权，不在 URL 中携带提取码；比较采用常量时间比较。
- 对鉴权失败按来源地址实施简单频率限制。公网部署仍要求使用 HTTPS/WSS 映射，避免明文传输提取码与日志。

## HTTP API

在现有 catch-all 403 之前注册以下接口，均要求有效提取码：

- `GET /api/log-admin/logs`：返回日志文件名、修改时间、大小及是否为当前服务端日志。
- `GET /api/log-admin/logs/{name}/preview`：返回单段 UTF-8 文本预览，单段最多 512 KiB，并标明是否截断；下载始终包含完整文件。
- `GET /api/log-admin/logs/{name}/download`：下载指定完整日志。

只允许访问日志目录内符合既有 `bwpro-*.log` / `bwpro_*.log` 规则的文件；严格校验文件名并拒绝路径穿越。文件在列表后被清理或提取码轮换时，请求返回明确错误，不暴露其他文件信息。

## 独立运维 GUI

- 新增 `python -m client.log_admin` 入口，使用现有 PySide6 可选依赖，不加载卡牌数据库、卡图或游戏界面资源。
- 首屏输入服务器地址与提取码；地址复用联机地址的host/端口/TLS口径，并转换为 HTTP(S) API 基础地址。
- 连接后展示日志列表：文件名、修改时间、大小和当前运行标记。
- 单击日志在线预览只读内容；支持多选并下载到用户选择的本地目录。
- 网络请求在后台线程执行，通过 Qt 信号回到主线程更新界面；鉴权失败、网络失败和文件失效以状态栏或小弹窗提示。
- 第一版不包含远程删除、清空、实时 tail，也不在主客户端联机页增加入口。

## 测试与文档

- 测试提取码生成、30 分钟轮换、旧码失效、文件权限及终端输出不进入日志。
- 测试未鉴权/错误鉴权、失败限流、日志列表、预览截断、完整下载、路径穿越和文件已删除。
- 测试玩家指令、拒绝原因、引擎事件与连接关闭均带足够排障上下文，且秘密字段不进入日志。
- 使用 offscreen Qt 测试运维端列表、预览、多选下载和错误提示。
- 更新 `server/README.md`、相关 GUI/运维文档及启动方式说明；Termux 服务端不增加 PySide6 等依赖。
