# BWPro 与 BWPDIY 双子域名部署设计

## 背景与目标

在同一台 Termux Debian 主机上运行 BWPro 联机服务与 BWPDIY Pyodide 在线本地版，通过两条独立 HTTPS 内网穿透映射发布到不同子域名。两者独立更新、运行和故障恢复，不引入同机反向代理。

BWPDIY 公网服务仅指 `prototype/pyodide/` 静态在线本地版；正式编辑器 8630/8631 及其项目读写 API 仍只允许本机使用。

## 拓扑与地址

```text
https://bwpro.varisox137.top  → 独立 HTTPS 隧道 → 127.0.0.1:1037  BWPro
https://diy.varisox137.top    → 独立 HTTPS 隧道 → 127.0.0.1:8640  BWPDIY
```

`diy.varisox137.top` 是部署文档示例，实际 DIY 子域名以花生壳配置为准。BWPro 客户端默认联机地址和地址解析规则不变；TLS 均在隧道边缘终止，本机两个服务不重复配置证书。

## 本项目改动

- 在 `server/README.md` 记录同机双服务拓扑、两个启动命令、两条映射和验收流程。
- 联机隧道必须支持 WebSocket Upgrade；DIY 隧道只需普通 HTTPS 静态资源访问。
- 日志运维端继续连接 BWPro 子域名的 `/api/log-admin/`，不经过 DIY 子域名。
- 不修改客户端协议、默认地址、房间流程、DIY 内容同步、日志鉴权或 Termux 启动脚本。
- 删除已被本设计取代的同域 Nginx 部署计划，以及已经实施完毕的旧选卡计划。

## 安全与数据边界

- 两个服务均仅监听回环地址，由对应隧道回连；公网不直接开放主机端口。
- 不暴露 BWPDIY 正式编辑器、项目目录或写盘 API；在线本地版只提供静态页面与运行时资源。
- DIY 草稿、卡图与布局仍只存浏览器；BWPro 房间内 DIY 内容同步仍走现有联机协议，不经过在线编辑器服务。
- 不开启 Uvicorn `proxy_headers`，不改变来源 IP、鉴权限流和重连校验。
- 两条隧道独立停止和回退；DIY 服务异常不得影响联机与日志管理。

## 验收

1. 本机分别访问 BWPro 1037 与 DIY 8640，确认进程和端口独立。
2. 通过 BWPro 子域名完成建房、加入、开局、一个回合和断线重连；日志提取码鉴权行为不变。
3. 通过 DIY 子域名打开页面、导出 PNG 并刷新恢复草稿；请求不进入 BWPro 服务。
4. 停止 DIY 进程后联机仍正常，停止 BWPro 进程后 DIY 页面仍可用。
5. 公网实测不可用或未执行的项目必须明确记录，不能用本机检查代替公网验收。
