# 本地卡图配置与合成缓存设计

## 目标

默认以项目根目录 `/library` 作为卡图配置库：用户手动运行根目录的 BWPDIY exe 完成标注，BWPro 在运行时使用这些美术配置与当前引擎数据重新合成卡面。不得把 exe 作为运行时服务，也不直接使用预先导出的完整卡图。

## 资源与职责

- exe：仅用于人工标注；当前为根目录下的版本化 exe，不由 BWPro 启动。
- `/library/<项目>/shikigami|cards/*.yaml`：提供图片路径、artwork 偏移/缩放/旋转、portrait、faction_style、可选 layout 覆盖和 version_date。
- `bwpdiy.render`：只负责进程内合成，沿用其 assets/layout，不引入 web/store/FastAPI。
- `CardDef`/当前 db：提供卡名、类型、等级、稀有度、效果文本、所属式神及全部数值；不得用配置中的旧文本覆盖当前引擎数据。
- 配置缺失、图片缺失或合成失败时，保留现有文字卡与菱形头像，不阻断构筑或对局。

## 版本与日期

- 配置按 `(id, version_date)` 索引，运行时按 `CardDef.version` 选择；不得按文件名或文件修改时间猜测版本。
- `version_date` 只接受整数或字符串形式的连续 8 位数字，并复用引擎日期合法性校验；不做分隔符自动清除。当前白狼/兵俑配置均为合法的 20191212，无需批量修改。
- 同 id 多版本配置必须共存；后续新增配置只影响对应版本缓存。

## 头像接入

`portrait.py` 将渲染资源根与用户配置根分离：框架 assets 仍由 `bwpdiy_root()` 提供，标注默认从项目 `/library` 读取。保留 `BWP_DIY_ROOT` 覆盖渲染库的能力，可增加独立的库路径覆盖。引擎 faction 优先于配置 faction，沿用现有大小、路径与像素限制。

## 卡图合成

新增 `client/gui/cardart.py`：

- 将 `CardDef.card_type` 映射到 BWPDIY 类型；等级、稀有度、所属式神、form/awaken/field/combat 数值由引擎映射。
- 原始 `[关键字]` 转为 BWPDIY `[[关键字]]`；力量/生命/护甲/破甲/能量/耐久/战力/乏力/赏金转为既有 `#xx` 图标代码，保持原文其他部分不变。
- 配置的 layout 覆盖可与引擎负载合并；配置的 description、power 等旧规则字段不得作为合成来源。
- `CardWidget` 与手牌卡面共享按需合成接口；有图时隐藏重复的文字基础区，保留操作按钮、已选张数和运行时详情区。
- 构筑静态详情保持兼容；对局增强、条件、委托和实时数值继续作为独立信息层，不烧进静态卡图。

## 缓存

采用进程内 QPixmap 缓存 + 磁盘内容寻址缓存：

- 每次先以当前引擎合成负载、规范化后的图片配置、图片文件 `mtime_ns+size`、BWPDIY 版本和 layout 内容计算 SHA-256；小 YAML 直接取内容，避免每次哈希大图。
- 磁盘文件为 `~/.bwpro/cardart/<hash>.png`；只有完整写入后才替换/复用，采用临时文件原子 rename，避免半图。
- 文本、数值、等级、爆能或其他合成相关数据变化会自然产生新键；配置不变即复用，不设置定时清理或基于时间的强制失效。
- 内存缓存有界；磁盘缓存不在本轮增加自动淘汰，后续如确需容量管理再单独设计。
- 渲染前限制 YAML 大小、异常数值、路径穿越/符号链接逃逸和估算像素，失败仅回退，不弹错误窗。

## 测试与文档

- 使用临时 library 与真实 BWPDIY assets 验证：项目库头像、按版本选配置、引擎文本覆盖配置旧文本、日期非法/缺失、同 id 多版本、缓存命中与文本变化产生新键、半图不复用、失败回退。
- 验证白狼/兵俑实际配置生成头像和全卡，检查浅深主题截图与操作按钮保留。
- 同步 GUI 文档、README/AGENTS 进度；全量 pytest 与 db.validate 由主上下文亲跑，codebase-memory 索引重建。

## 非目标

- 不启动或调用 exe/HTTP 服务，不导入 BWPDIY web/store 层。
- 不把所有式神批量生成完整卡图入库，不修改 `/library` 用户内容。
- 不把运行时增强写回配置，不实现磁盘缓存自动清理或卡图动画。
