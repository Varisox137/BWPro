# 对局场景与实时卡面详情设计

日期：2026-10-26

## 目标与范围

依据 `gui_ref/对局ui参考.png` 重做桌面 GUI 的对局画面，尽量还原原版的卡面布局、拖拽出击/用牌与目标选择。点击式神或手牌打开详情，并尽可能通过本地 BWPDIY 渲染库按当前引擎状态绘制卡面。

本轮采用 PySide6 `QGraphicsScene/QGraphicsView`，不重写规则引擎、联机协议、卡组构筑与结算队列。首先接入现有本地热坐；场景组件保持可复用，不要求本轮改造联机 GUI。运势、倒计时、卡牌飞行等正式动画不在本轮实现，但场景分层和坐标体系统一为后续动画预留。

## 方案选择

采用场景视图而非继续堆叠 QWidget 绝对布局：

- 卡面、牌手、牌库、落点、高亮与拖拽箭头统一使用场景坐标和 z-value。
- 拖拽命中以图元实际位置为准，后续位移、缩放、旋转动画不会破坏另一套手工坐标。
- 后续可用 `QGraphicsObject`、`QTimeLine`/`QVariantAnimation` 实现统一动画层。
- 现有 `HotseatView` 继续管理 `Game`、指令、timeline、热坐交接和隐私；`QDialog` 继续承担详情、使用方式和结算选择。

## 组件划分

新增独立的对局场景模块，避免继续扩大 `client/gui/battle.py`：

- `BattleScene`：维护逻辑分辨率、图元层级和场景坐标。
- `BattleCardItem`：显示卡图、透明占位或式神彩色框，暴露卡牌 uid、式神 `Ref` 等身份，不改变规则状态。
- `BattlePlayerItem`：牌手头像、生命/护甲、鬼火、出击和鼓舞摘要。
- `BattleDropZone`：牌手、式神、战斗区与普通场地区域的落点识别。
- `BattleDragController`：处理按下、拖拽阈值、半透明拖拽副本、箭头、合法落点和取消；只产生 UI 操作请求。
- `BattleSceneController`：把当前 `Game.state` 映射为图元，并把拖拽结果转换为现有指令调用。
- `BattleAnimationLayer`：本轮只规定独立 z 层与接口边界，不添加正式动画队列。

`HotseatView` 保留为对局页面宿主与规则交互控制器。场景通过 signal 请求详情、出击、用牌、升级和结束回合，不直接调用 `Game.apply`。

## 对局布局与美术

使用固定逻辑场景尺寸，按窗口等比缩放，剩余区域留边；布局以参考图的相对位置为准，而不是沿用现有上下三行布局：

- 敌方牌手位于左上，己方牌手位于左下。
- 双方式神排布于上下半场，准备区为缓和弧线，战斗区位于中央；当前视角始终己下敌上。
- 双方手牌分别位于右上、右下，以较小卡面覆盖在式神图元上层；限制整体高度，允许横向重叠，12 张手牌时可以遮住部分式神卡，不为了保持式神可见而过度缩小手牌。
- 双方手牌均按 `CardInstance.hand_seq` 的入手顺序排列。敌方未展示手牌只画卡背，本轮可用占位卡背；`mods["revealed"]` 为真的敌方手牌在原顺序位置改画真实卡面，不另设独立展示区，也不泄露其他手牌内容。
- 右侧中央为结束回合，敌方/己方牌库在其上下；左侧中部为战斗记录，右上为菜单。
- 移除卡面周围常驻文字底板和按钮栏。费用、等级、力量、生命、护甲和倒计时等以角标呈现；详细状态留在详情弹窗。
- 合法目标、可出击/可升级状态使用描边、光晕或角标。操作提示只在悬停、拖拽或相应阶段出现。
- 手牌和形态卡优先复用 BWPDIY 卡面渲染；没有匹配卡图时使用全透明图元占位，保留固定尺寸、命中区域和详情入口，不伪造文字卡图。
- BWPDIY 的式神卡渲染尚未完成，本轮场上及详情中的基础/觉醒式神统一用彩色框占位，显示式神名、等级、力量与生命；详情另显示对应能力文本。后续只替换式神图元的绘制适配，不改变布局和交互。

## 拖拽交互

### 基本状态机

1. 左键按下可交互卡面，记录源图元、场景坐标与候选指令。
2. 位移未超过 `QApplication.startDragDistance()` 时，松开视为点击查看详情。
3. 超过阈值才进入拖拽：源卡降低不透明度，显示半透明卡面副本和从源中心指向光标的箭头，并按操作类型计算落点。
4. 在原图元区域或无效位置松开，取消本次拖拽，不出击、不用牌。
5. 在有效落点松开，仍由现有引擎入口做最终合法性校验；非法操作沿用当前错误提示，不在 GUI 复制规则。

拖拽期间不修改手牌、式神或战斗区的真实状态。视角交接、结算播放、结算选择或胜负已分时禁止开始新拖拽，并取消现有拖拽视觉状态。

### 式神出击

- 仅当前行动方、对战阶段且可出击的己方式神可成为拖拽源。
- 非追猎式神不要求落到敌方牌手或战斗区：拖出源式神范围后，在其他位置松开即提交默认目标的 `assault`，与原版交互一致。
- 追猎式神必须落到高亮的合法敌方角色上，提交对应 `target`；落在其他位置仍取消。
- 升级不使用拖拽；升级阶段点击可升级式神或其明确操作入口。

### 手牌使用与目标

- 无目标牌：拖出手牌区域并在有效场地区域松开，提交 `play_card`。
- 有目标牌：直接拖到合法角色上松开，提交带 `target` 的 `play_card`。
- 爆能、协战子选项等多种使用方式：在合法落点松开后显示现有方式选择弹窗；若所选方式不接受原落点，则取消本次操作并保留手牌。
- 当前没有主动多选目标的卡牌/效果，本轮不新增连续拖拽选第二目标的交互；保留现有多目标数据路径，不为其扩展场景状态机。
- 调度阶段将卡牌拖出手牌区域进行调度；点击仍只查看详情。原“使用/调度”按钮可作为无障碍兜底，但不作为常驻画面主体。

## 实时卡面渲染

### 配置与负载分离

扩展 `client/gui/cardart.py`，将“用于选择 YAML/卡图的定义”与“实际送入 BWPDIY 的显示负载”分开。现有 `card_pixmap` 保持静态调用兼容，新增运行时入口复用同一布局合并、安全检查、渲染和内容寻址缓存，本轮主要用于手牌和形态卡。

运行时数值必须进入规范化 payload 和缓存键；不改写引擎实例，不启动 BWPDIY exe，不修改 BWPDIY 项目。配置仍只提供 artwork、layout 与 faction_style，名称、文本和数值由 BWPro 当前状态生成。

### 手牌卡面与详情

- 有卡图的手牌缩略卡和详情大卡使用同一实时负载；无卡图时场上使用透明占位，详情保留现有文本信息，确保内容仍可查看。
- 在 `client.cli.hand_cards_info` 的现有展示信息之外提供结构化渲染数值，避免 GUI 解析“力量+2/身材3/4”等中文标签。
- 战斗牌力量/护甲、形态身材、觉醒永久修正和增强数值由现有引擎求值入口生成；当前费用、关键字、委托、使用条件与使用方式继续显示在辅助详情栏。
- 本轮不重写卡牌原始效果文本；动态数值进入适用的卡面数值位，无法结构化的增强信息保留在辅助详情栏。

### 式神详情

新增式神详情弹窗，主区域显示当前能力卡；若有形态，则并列显示形态卡，下方保留完整运行时状态列表。

- **未觉醒主卡**：使用彩色框式神占位，显示基础式神名、等级、基础力量/生命和基础能力文本。
- **已觉醒主卡**：使用带觉醒标识的彩色框式神占位，显示觉醒牌名称、当前等级和觉醒能力文本；暂不调用尚未完成的 BWPDIY 式神卡渲染。
  - 力量 = 式神基础力量 + `perm_power`（其中已包含觉醒与其他永久修正）。
  - 生命 = 式神基础生命 + `perm_health`。
  - 不加入临时修正、战斗修正、动态光环、灵咒或当前生命损耗；这些在状态区另列。
- **形态卡**：尽可能使用 BWPDIY 渲染形态自身卡图、文本与 `form_power/form_health` 基础值，不叠加觉醒、永久/临时修正或灵咒；缺卡图时按透明占位加现有文本详情处理。
- 当前生命、永久/临时/战斗修正、关键字、倒计时、延迟能力、灵咒、眩晕与气绝等继续使用现有完整状态区，并维持非公开目标仅持有方可见的规则。

## 缓存、错误与隐私

- 沿用 `~/.bwpro/cardart/<sha256>.png` 与有界内存缓存；运行时数值、当前外观和实际 layout 均参与缓存键。
- 沿用 YAML 大小、图片像素、路径穿越与 layout 数值安全检查；异常仅触发回退，不中断对局。
- 测试通过临时 HOME 和临时配置库隔离真实缓存。
- 热坐交接时清空拖拽副本、箭头与手牌图元，避免泄露上一方非公开信息。
- 战斗记录继续过滤对方调度信息；运行时详情不额外暴露秘密选择。

## 测试与验收

- 场景布局：双方视角、弧线/战斗区、双方手牌按 `hand_seq` 排列与叠放层次、12 张手牌覆盖、右侧操作区和常见窗口尺寸。
- 敌方手牌隐私：未展示牌只有卡背，已展示牌在原顺序位置显示真实卡面，其余定义和文本不可由图元读取。
- 鼠标交互：点击打开详情；未超阈值不用牌；拖回原位/无效区域取消；非追猎式神拖出源范围即出击、追猎必须命中合法目标、无目标牌与目标牌生成正确指令。
- 多使用方式：合法落点与方式不匹配时不提交指令；不虚构主动第二目标用例。
- 详情负载：基础、觉醒、觉醒加形态三种情况；式神暂用彩色框，觉醒永久身材与形态基础身材严格分离。
- 手牌结构化实时数值与中文展示标签保持同源；运行时变化产生新缓存项。
- 缺手牌/形态卡图时使用透明占位，缺式神渲染时使用彩色框；拖拽与详情仍可用。
- 热坐交接、timeline 播放和结算选择期间无法拖拽，且无隐私泄露。
- 更新 `docs/gui-design.md`、必要的 GUI 文档与测试；最后运行全量 `pytest`。本轮不改卡牌数据，无需因 UI 改动运行数据迁移。

## 非目标

- 不实现正式运势、倒计时、伤害或飞行动画，只预留场景和动画层。
- 不重写联机协议、服务端、规则引擎或 BWPDIY。
- 不补齐尚未人工标注的卡图，不修改 `library/` 用户内容。
- 不实现逐条增减益来源账本、关键字解释面板或新的牌库查看功能。
