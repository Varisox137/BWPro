# 对局界面与运行时详情改造设计

## 目标

调整 PySide6 对局界面，使其更接近原版的布局与交互，同时保持热坐、联机共用组件和现有目标选择逻辑。只改 GUI 展示层，不改引擎结算、卡牌数据或联机协议。

## 已确认方案

采用布局容器方案，不使用绝对定位或自绘牌桌。保留 `ShikiFrame.ref`、`pi/index`、信号与字典键，避免破坏单目标、双目标和状态刷新。

## 对局布局

- 删除顶部 `seat_label` 及 `cli.format_seat_line` 的 GUI 调用，CLI 保留不变。
- 左侧栏从上到下为敌方牌手、战斗记录按钮、己方牌手；中央为双方式神准备区与战斗区。
- 热坐与联机都固定“己下敌上”：上方为 `1 - viewer`，下方为 `viewer`。仅在 viewer 改变时重排既有牌手与式神通槽，不重建组件、不改 `Ref`。
- 四式神通槽通过固定容器上下间距形成轻微弧线，不在常规刷新时移动或重建槽位。
- 常态式神组件只显示等级、名字、倒计时（如有）、当前力量、生命、护甲；不显示编号、能量、形态、关键字、灵咒等详细信息。名字、数值等标签使用透明背景、无边框，仅保留式神槽自身样式。

## 战斗记录

- 新增由 `HotseatView` 持有的非模态日志 `QDialog`，默认隐藏。
- 左侧中部按钮重复打开同一窗口；现有 `log_list`、时间线播放和按视角过滤逻辑复用。
- 关闭窗口只隐藏，不清空记录；重新打开滚动到底部。
- 开局、返回主菜单和联机会话重置时关闭窗口；日志窗口打开时仍需遵守非公开信息过滤。
- 起始调度阶段“调度了一张手牌（剩余 N 次）”仅所属玩家可见，不能因换视角或重放记录而泄露给对方；战中相似文本不被起始阶段过滤误删。联机沿用服务端既有脱敏，不改协议或 CLI。

## 热坐交接

- 每次 viewer 切换（调度、回合结束、跨玩家 pending_choice 及作答后返回）先显示“当前玩家行动结束，请确认后由对方行动”模态小弹窗。
- 确认前清空/隐藏上一玩家手牌与候选选择、冻结全部指令、暂停时间线播放和上下半场重排；不能只禁用按钮而继续暴露手牌。
- 确认后重排为己下敌上、显示新玩家手牌、恢复时间线和 pending_choice。相同玩家连续操作不弹交接，联机固定 `me`，不启用热坐交接。

## 弹窗与提示音

- 对局内牌手详情由 `QMessageBox` 改为普通 `QDialog`，避免系统信息框提示音；不新增音频功能。
- 标准弹窗按钮继续复用 `polish_dialog_buttons`：中文文案、`dialogButton` 样式、内容底部右对齐、统一高度与紧凑宽度。
- 必答的 `ChoiceDialog.reject()` 语义不改，不增加绕过强制选择的取消操作。

## 卡牌运行时详情

- `CardDetailDialog` 增加可选运行时信息参数；构筑等静态场景不传时保持现有显示。
- 对局打开手牌详情时读取当前 `hand_info`，追加“当前状态”区：
  - 当前费用与实时数值文本；
  - 增强计数、当前关键字、委托进度；
  - 使用条件是否满足，以及现有使用方式中的合法性/原因。
- 原始效果文本不改写，GUI 不自行重算增强或动态数值。联机只读服务端 `payload["hand_info"]`，热坐调用同一 CLI 求值入口。
- 实时含义为打开详情时读取最新状态，不要求弹窗打开期间随推送自动刷新。

## 式神运行时详情

在现有基础、觉醒、形态文本之上，补充当前有效力量与生命、护甲、能量、倒计时、关键字、眩晕/气绝、灵咒等已有序列化状态。仅展示现有分类与合计，不承诺逐条增减益来源账本，不新增通用回合/本局事件计数。

## 异常与兼容性

- 日志窗口重复打开不创建新实例；退出和重连不得留下悬空窗口或计时器。
- 无运行时详情参数时，卡牌详情保持静态行为。
- 热坐切换视角、联机固定己方视角时，日志和详情均不得展示非公开信息。

## 测试与文档

- 更新 GUI 测试：顶部座位行移除、常态式神字段精简、日志默认关闭与复用、返回/重连关闭日志、牌手与式神组件数量及目标选择不变。
- 增加己下敌上重排且对象/`Ref` 不变、热坐交接前隐藏手牌并冻结输入、确认后恢复、起始调度记录分视角过滤测试；联机不出现热坐交接。
- 增加卡牌运行时详情、委托进度、联机 `hand_info` 来源和式神详细状态（含逐条灵咒）测试；静态详情兼容性保留。
- 按钮验证中文角色和尺寸约束，不做跨平台像素位置或提示音断言；Windows 下人工确认无系统提示音。
- 检查浅色/深色截图，运行 GUI 定向测试、全量 pytest、`db.validate` 并重建 codebase-memory 索引。
- 同步 `docs/gui-design.md` 与 `docs/gui-plan.md`，不将逐条增益来源账本标为完成。

## 非目标

- 不重写牌桌渲染、不引入 3D/动画/音效。
- 不修改规则引擎、卡牌数据库、CLI 座次文本或联机协议。
- 不实现弹窗打开期间的实时自动刷新、通用条件进度账本或逐来源增减益列表。
