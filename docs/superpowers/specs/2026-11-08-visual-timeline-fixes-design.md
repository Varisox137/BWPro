# 对局视觉时序与 GUI 回归修复设计

## 目标

修复牌库与战斗区布局、热坐交接、战斗/运势/倒计时/复活/升级动画的时序问题，补充抽牌与生成入手动画、同效果数值刷新合并及零伤害动画，同时解决已复现的五项旧 GUI 回归。

规则引擎仍立即结算 `GameState`；GUI 通过结构化视觉事件及事件快照延迟更新呈现状态。不得为动画改变战斗、插入结算、气绝检查或光环判断的规则次序。

## 已确认根因

- 战斗区普通布局与移动动画分别计算横坐标，导致先移至偏右位置再纠偏。
- 己方牌库已反转位置索引，但旋转仍使用旧索引，位移与角度不对称。
- 热坐交接会清空尚未播放的旧回合动画，并在补播新回合事件前同步最终场况。
- `defeated` 在入队时就应用灰阶和最终气绝状态，早于其前的移动、伤害和扣血动画。
- 普通倒计时、气绝倒计时、复活、入手和部分动态光环变化缺少结构化视觉事件。
- 升级阶段没有等待回合开始视觉队列，升级完成后的轮廓与升级遮罩也未按新卡图重建。
- 每个数值 op 都单独生成 `stat`，同一效果的多次增减被拆成多段。
- 护甲、屏障或减伤将正伤害归零时提前返回，没有生成可显示 `-0` 的伤害视觉事件。
- 旧回归中，原生尺寸用例直接导入未初始化的 `bwpdiy`，护甲用例只等待文字队列；小卡渲染用例错误限制重绘次数。透明兜底失败来自全局布局读取路径的目录创建副作用。

## 方案选择

采用“结构化视觉事件 + 快照回放”。不采用 GUI 前后状态猜测，因为无法可靠还原重投同点数、倒计时归零后重置等中间态；也不延迟规则状态，避免影响后续效果判断。

## 事件与顺序

### 战斗

统一战斗区坐标helper，普通布局和移动动画共用。战斗呈现顺序固定为：

1. 出击字样。
2. 攻击方移入战斗区。
3. 双方伤害数字并行。
4. 双方扣血及小卡刷新并行。
5. 双方气绝字样并行，并应用气绝快照。
6. 双方以气绝状态移回准备区并行。

`defeated` 的灰阶、倒计时及卡图副作用在事件出队开始时应用；事件结束后仍使用该事件快照，不能读取后续最终状态。有待播事件时，已有图元不得被普通 `refresh()` 隐式吸附到最终位置。

### 运势与光环

将视觉事件拆为 `luck_dice`、`luck_reroll`、`luck_result`。首骰在 `on_luck_judge` 插入结算前发出；重投顺序为首骰、重置、新骰、最终结果。是否重投以显式标记判断，不能以点数是否变化判断。保留旧 `luck` 的 GUI 兼容读取，文字对局记录与运行日志不重复、不改写。

动态光环重算后比较旧值与新值，仅对实际变化目标追加 `stat`；同批不同目标共享并行动画组。青蛙瓷器等光环变化应位于运势结果之后、后续移动及战斗伤害之前。

### 倒计时与复活

新增倒计时变化、归零能力开始及复活视觉事件，携带普通倒计时、气绝倒计时、气绝状态和必要身材快照：

- 普通倒计时先显示实际减少后的值，归零能力随后播放，再显示重置或移除。
- 气绝倒计时 1→0 先显示仍为气绝的 0；播到复活事件后才恢复未气绝卡图。
- 所有直接修改相关倒计时的路径使用统一内部辅助，避免只覆盖自然回合开始。
- 永久气绝的无限标记与“即将复活的 0”通过快照标志区分。

### 入手

在统一卡牌移动入口为实际进入手牌生成视觉事件，覆盖抽牌、生成、检索和回手；爆牌不生成。事件不携带可向敌方泄露未展示卡牌的信息。

GUI 复用现有手牌图元和位移动画：抽牌从对应牌库进入，生成牌从对应牌手区域进入；多张牌按事件顺序播放。动画开始前隐藏最终槽位中的新牌，结束后仅保留一个图元。敌方未展示手牌使用卡背。

## 热坐与输入门控

在回合开始处加入视觉边界。热坐结束回合后：

1. 旧玩家继续播放边界前的回合结束用牌及效果动画。
2. 旧队列全部结束后才隐藏手牌并显示“切换玩家”。
3. 新玩家确认后重绘视角，再播放边界后的回合开始、抽牌、运势、倒计时和复活动画。

暂存条目同时保留卡牌使用与视觉事件，不得在交接期间丢弃。确认交接时，待播事件也参与最终状态延迟，避免复活等状态提前出现。

仅在升级阶段视觉队列未排空时锁定主动输入并隐藏升级遮罩；文字对局记录不作为解锁条件，主要阶段继续允许非阻塞连续操作。每次升级动画结束后重建小卡、焦点轮廓和升级徽标，再开放下一次升级。

## 布局与数值表现

- 牌库三张卡使用一致的相邻位移和旋转增量；己方与敌方按垂直镜像位置对应。
- 战斗区动画终点以当前正确普通布局为准，不再使用另一套全场景居中公式。
- 同一效果块内、同一目标且相邻的 `stat` 合并，首个事件更新为最新快照；跨伤害、移动、气绝或嵌套触发能力不得合并，多目标保持并行。
- 正伤害因护甲、屏障或减伤归零时生成 `damage(amount=0)`。原始 0 伤、免疫、伤害取消、转移或转化为其他事件时不生成 `-0`，规则结算仍不扣血、不触发受伤后续。

## 旧回归处理

- 原生尺寸测试先通过项目既有渲染器初始化路径，再导入 `bwpdiy`。
- 护甲测试同时等待视觉队列，而非只等待文字记录。
- 小卡渲染测试验证当前八式神均经过 DIY renderer，不限制允许的后台重绘次数。
- 透明兜底在 BWPro 侧提供只读布局降级，不修改 sibling BWPDIY 源码；不得因缓存目录不可写而返回空卡图。
- 战斗区坐标冲突随统一 helper 修复，相关硬编码断言改为引用同一布局结果。

## 测试与验收

每组先增加能复现原始问题的失败测试，再实施最小修复：

1. 布局与旧回归：牌库镜像、战斗区坐标、只读兜底、原生尺寸、护甲最终同步、小卡渲染覆盖。
2. 战斗与运势：逐步驱动 GUI 验证移动、伤害、扣血、气绝、回位；验证重投顺序、同点数重投、光环插入点和日志计数。
3. 热坐与阶段：回合结束动画先于交接，新回合动画属于新视角，倒计时与复活不提前落地，升级遮罩和输入在视觉队列后排空才开放，连续升级轮廓刷新。
4. 入手与数值：抽牌/生成/爆牌及隐私、同源 `stat` 合并边界、并行目标、`-0` 与免疫/转化负面对照。

每批运行相关定向测试与 `git diff --check`，通过后分别提交并推送。最后运行完整 GUI 回归和引擎相关测试；改动引擎视觉事件后同步 `docs/gui-design.md`、`docs/gui-plan.md` 及必要术语/事件文档。无需修改卡牌数据，不运行无关的耗时全量冒烟。
