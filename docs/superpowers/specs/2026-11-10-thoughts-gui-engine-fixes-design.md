# thoughts.txt 十项问题修复设计

## 目标

落实 `thoughts.txt` 的十项渲染、交互和规则修复，保持既有结构化视觉事件、快照回放、热坐两段交接和联机隐私契约。采用分组定点修复与图元级复用，不重写整体卡图缓存。

## 已确认事实

- 当前渲染代码来自 BWPDIY 1.8.4，美术资源来自本项目 `assets/`。
- libpng iCCP 警告在空白 Qt Windows 原生窗口也会出现，与项目图片无关；Python `warnings` 和 Qt message handler 均无法捕获该原生 stderr。
- 小卡文字色块是 pixmap 渲染失败后的既有兜底；倒计时 0 和濒死负生命会触发 BWPDIY 参数校验失败。
- 怪力与不屈均为引擎规则实现问题，不是单纯显示问题。
- 热坐和联机都在视觉队列未排空时立即显示胜负字样。

## DIY 与渲染

1. 从 BWPDIY 同步 `assets/levels/evolve_circle.png` 到本项目同路径，启用新版觉醒纯色圆盘；沿用现有资源指纹失效机制。
2. 不修改 BWPDIY 实现；在 `BWPDIY/docs/bwpro-integration-feedback.md` 记录气绝倒计时 0 的支持建议。BWPro 在倒计时 0 的过渡帧保留上一张有效小卡，等待紧随其后的复活事件再更新，避免传入非法参数。
3. BWPro 的 `entity_pixmap` 在呈现边界将快照 `power/health` 钳到 `max(0, value)`；引擎濒死结算仍保留原状态。
4. 用真实渲染覆盖负生命和整个气绝/复活链，断言 pixmap 非空且小卡尺寸不跳变；倒计时 0 过渡帧不得触发文字色块。
5. 不修改 PNG、不过滤全局 stderr；仅将 libpng 文档修正为 Qt Windows 原生平台窗口的无害上游警告。

## 牌库与空库状态

1. 非空牌库创建 `min(3, len(deck))` 张卡背，并从外向内减少：己方保留索引前缀，敌方保留索引后缀，顶部图元与抽牌动画起点一致。
2. 空库只在顶部位置保留一张：`player.ext["deck_out_burn"]` 存在时使用 `empty_deck_light.png`，否则使用 `empty_deck_dark.png`。不通过式神是否在场判断觉醒书翁效果。
3. 空库素材裁掉黑色侧栏，使用与普通牌背一致的布局尺寸；卡背设置刷新和窗口 resize 不得恢复普通卡背或丢失特殊布局。
4. `named_cardbacks()` 排除两个内部空库素材，避免出现在用户卡背设置中。
5. 牌库整组位置索引反转且图元角度增加 180°；图片预先额外旋转 180°抵消，因此最终卡背朝向仍为原图上方向左。普通同步和 viewport resize 共用同一位置/角度计算。

## 调度与选择交互

1. 进入确认调度后的最终起手回顾时清空 `mulligan_uid`，所有手牌缩放恢复 1.0；正常选择过程仍保留放大反馈。
2. 选择视图按“选中卡高 + 按钮高 + 间距 + 内容边距 + 边框 + 实际横滚动条”计算最小高度；删除对话框对 450 的覆盖。选中变化后更新几何尺寸，保证按钮完整落在 viewport 内，并缩小顶部说明与卡图、卡图与按钮的多余间距。
3. 点击选择后立即关闭或禁用旧选择窗，再在下一事件循环执行作答；失败时恢复选择窗。该措施只负责即时反馈，不冒充性能优化。
4. `BattleScene.sync_state` 为式神和手牌保存生成 pixmap 所需的状态签名，未变化时直接复用当前 pixmap；生命、形态、等级、显示修正、卡背/主题等影响内容的字段变化时必须重绘。资源指纹和内容散列的缓存失效语义不得削弱。
5. 性能回归用渲染函数调用次数验证，不使用易波动的墙钟阈值。

## 规则修复

### 怪力及同类战斗牌

仅修改战斗牌身材入口：`shield > 0` 继续按获得护甲处理；`shield < 0` 改为 `kind="fragile", delta=-shield`，即获得破甲。不得修改通用 `_change_shield` 的负 delta 规则。覆盖默认环境怪力、已有护甲时先抵消，以及腐坏直拳同类路径；20191212 版怪力无破甲仍是正确行为。

### 不屈

引入仅用于生命扣减步骤的 `health_loss`。不屈生效时只钳制 `health_loss`，不改写 `ev.amount`；伤害视觉、伤害日志、`ev.dealt`、`damage_taken_turn`、`on_damage`、伤害插入帧和吸血继续使用原伤害量。日志的生命变化显示实际扣减前后值。

### 胜负动画

在共用结果入口等待 `battle_scene.visual_busy == False`，动画排空后的既有 `animations_settled` 信号再次触发显示。覆盖本地/联机致死伤害与特殊胜利；`winner=None` 的断线或主动终止提示不等待。
